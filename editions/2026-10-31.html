01late catch, 29.10: גרסה זדונית של תוסף Claude Code בשוק של Cursor - דלת אחורית SSH במשך ~11 שעות+

מה זה ולמה כאן

late catch: ההתראה הרשמית של Cursor פורסמה ב-29.10 ולא נתפסה בסריקת 30.10 - עדיין בתוך 48 שעות. זו לא איום תיאורטי: חלון חשיפה אמיתי שכבר נסגר, עם צעדי בדיקה שצריך להריץ אם התקנת תוסף ב-Cursor באותו יום.

מה קרה

בין 02:27 ל-13:35 PT ב-29.10 הייתה זמינה ב-Cursor VS Code Extension Marketplace גרסה ששונתה בזדון של התוסף Anthropic.claude-code (2.1.312 ו-2.1.313, ל-Windows ו-macOS). הגרסאות הזדוניות לא פותחו על ידי Anthropic, וההפצה הרשמית (npm, שוק ה-VS Code הרשמי) לא נפגעה - רק מי שהתקין או עדכן דרך השוק של Cursor בחלון הזה.

מה ה payload עשה

איסוף ודיווח מידע על המארח (hostname, משתמש, OS, נתיבי עבודה, Git email, IP ציבורי); ניסיון להוסיף מפתח SSH של התוקף ל-authorized_keys, להדליק שירות SSH מקומי ולפתוח מנהרה הפוכה (נכשל ברוב המכונות בגלל חוסר הרשאות admin ושגיאות בקוד); והתקנת persistence - LaunchAgent ב-macOS או Scheduled Task ב-Windows, עם ניסיון חוזר כל ~60 שניות. חשוב: הסרת התוסף לא מספיקה - ה-payload משאיר סקריפטי persistence עצמאיים. שרת התוקף כבר הושבת, אז הדליפה הפעילה והמנהרה לא מתפקדים כרגע.

בדיקה ותיקון

בדיקת הנגיעות היא שורה אחת: grep -qs svc-telemetry ~/.ssh/authorized_keys (macOS/Linux) - המפתח של התוקף מתויג svc-telemetry. אם נמצא: לבודד את המכונה, להסיר מפתח + persistence + תהליכי tunnel (Cursor מצרפת סקריפטי remediation לשני המערכות), ולסובב credentials שנגעו במכונה - ממערכת נקייה. Cursor הסירה את הגרסאות, סגרה את כל השוק מחדש זהירות, בדקה שלא נפגעו תוספים אחרים, סובבה מפתחות ובנתה את השוק מחדש.

איך לקרוא את זה

המתקפה פגעה בנקודת החולשה של שווקי תוספים משניים: אותו שם, אותו מוצר, ערוץ הפצה אחר עם שרשרת חתימה שבורה. הדפוס מוכר מניסיונות על npm/PyPI - עכשיו הוא מגיע לכלים שמריצים סוכנים עם הרשאות רחבות על המכונה שלך.

חיבור אפשרי לפרויקטים שלך: אם אתה או מישהו בצוות עובד ב-Cursor - בדיקת ה-svc-telemetry היא 30 שניות על כל מכונה. והלקח הכללי ל-dorgames ולמענה: להתקין תוספי סוכנים רק מהערוץ הרשמי של היצרן, ולדעת איזה שוק משרת את ה-IDE. זו שאלת בדיקה, לא דיווח על חשיפה קיימת.

02Claude Code 2.1.316: מאמץ נפרד לתת-סוכנים, תקציבים קבוצתיים, ודדליין ל-fast mode של Opus 4.8+

מה פורסם

v2.1.316 ב-31.10 ב-01:01 UTC. שים לב למספור: ה-CLI הרשמי מדלג על 2.1.313 לגמרי (312 → 314 → 316) - רלוונטי על רקע כרטיס 01, גם אם אין קשר רשמי מוצהר.

יכולות

CLAUDE_CODE_SUBAGENT_EFFORT - רמת מאמץ נפרדת לתת-סוכנים במקום לרשת את הסשן; שקול לכרטיס Fusion מ-29.10, בגרסת הקונפיג שלך. תקציבים קבוצתיים מאוחדים ב-gateway של Claude apps (pooled_budget): תקציב חודשי משותף לקבוצה מעל המגבלה האישית. managed.policy_mode: layered - כל policy שמתאים למפתח חל, בשכבות, לא רק הראשון. guardrail.input_tagging ל-upstreams של Bedrock - עטיפת פרומפטים בתגיות שמסנן prompt-attacks של Bedrock מצפה להן. CLAUDE_CODE_DISABLE_ULTRATHINK מכבה את מילת המפתח.

לשים לב

fast mode ל-Opus 4.8 מיושק: מוצא משימוש ב-30.10 ויוסר ב-30.11 - אחרי ההסרה בקשות fast יחזירו שגיאה בלי fallback. מי שמשתמש: לעבור ל-Opus 5.5. ושוב ערכת ה-CA: CLAUDE_CODE_DISABLE_LOOPED_CROSS_CERT_DROP לשרתים שה-CA הפרטי שלהם דורש תעודות צולבות בלולאה, והודעות שגיאת SSL משופרות שמנקות סיבה ותיקון לכל מקרה.

תיקונים בולטים

סשני --restricted לא יעלו עוד קבצים מחוץ לתיקיות העבודה גם כשכלל Read מתיר (משלים את blockWritesOutsideWorkingDirectories מ-2.1.314). פקודות shell לא נשארות רצות כש-Claude Code יוצא. מודלים על Vertex/Bedrock עוברים לגרסה ישנה יותר בשקט כשהחדשה עוד לא זמינה באזור. ה-gateway בודק כל מודל בבקשה מול רשימות החסימה ומחזיר 400 עם שם השדה.

חיבור אפשרי לפרויקטים שלך: CLAUDE_CODE_SUBAGENT_EFFORT שווה ניסוי על ריפו של מענה או dorgames - תת-סוכנים על low כשהסשן על high חוסך בלי לפגוע בתשובה הראשית. ומי שעל Opus 4.8 fast mode - יש 30 יום למעבר. זו הצעה, לא דיווח על תצורה קיימת. הסתייגות: קראנו את רשימת הגרסה ולא הרצנו אותה.
