רדאר 03.10: איפה deny ב-Claude Code מחזיק, מודלי החלטה מקומיים ו-MCP של Supabase

שלושה אותות מעשיים: תנאי ההגנה מול mods ב-Claude Code, נקודת קצה חדשה ב-llama.cpp למודלי החלטה, ו-Supabase שמביאה סכמה ו-MCP לריפו.

01Claude Code: חוקי deny מחזיקים מול mods רק כשהמגן מותקן+

מה קרה

אתמול כתבנו על Mods ב-2.1.287. היום יצא המשך חשוב: בקוד הפתוח של Anthropic, בתיקיית mods/sec-default, מתואר מגן שמחזיק את חוקי ה-deny מול mod שמשתמש התקין. מבלי המגן, mod יכול לענות על tool.check בהחלטה "allow", והבדיקה מעל חוק deny לא תחזיק. לפי ה-README, הוא מותקן אוטומטית רק במחשב עם managed settings או בארגון Team או Enterprise. ה-README גם אומר שאם מפעילים אותו עם --plugin-dir הוא רק עובר הלאה ולא מגן.

אתר AINews פרסם ב-2.10 בדיקה עצמאית על Max בלי managed settings: mod של שבע שורות שהותקן ממרקטפלייס הריץ פקודת Bash שחוק deny חסם, בלי הודעה ובלי prompt. לא שחזרתי את הבדיקה בעצמי. התיאור שלהם מתאים למה שכתוב ב-README, ולכן אני מתייחס אליו כבדיקה תומכת ולא כראיה עצמאית. אותו מקור מראה ש---safe-mode או "disableAllHooks": true מנעו את ה-mod באותה ריצה.

בגרסה 2.1.288 (2.10, 20:19 UTC)

יש כמה תיקונים שמשפיעים על עבודה יומיומית: שיחות ארוכות שנכשלו עם "Prompt is too long" במקום לעשות compact אוטומטי, resume שאיבד קבצים או את התשובה האחרונה, timeout באמצע תשובה שכשל תור (עכשיו ממשיכים מהתשובה החלקית, לא אינטראקטיבי ו-subagents), ו-hook מסוג tool.call של plugin ששבר Bash בתת-סוכנים ב-worktree. נוסף גם prompt להתחברות מחדש כששרת MCP מבקש OAuth scope נוסף באמצע קריאה, ו-/code-review --max-findings.

החיבור אליך: בדוק דבר אחד: claude plugin test ו-claude plugin validate על כל plugin שמותקן אצלך, ועל איזה סוג חשבון אתה. אם אתה על Pro, Max או מפתח API בלי managed settings, אל תניח ש-deny בהרשאות מחזיק מול plugin של אחרים; התקן רק קוד שקראת. מי שעובד על מענה, podcasto ו-dorgames בסשנים ארוכים ירוויח מ-2.1.288 בעיקר מהתיקונים ל-resume ול-compact, אז שווה לעדכן אחרי smoke test קצר.

02llama.cpp מריץ מודלי החלטה מקומית עם נקודת קצה /v1/systemone+

מה יצא

ב-2.10 (ה-PR מוזג ב-09:56 UTC, הפוסט ב-Hugging Face ב-14:22 UTC) נוספה ל-server של llama.cpp נקודת קצה /v1/systemone. שולחים state (טקסט, JSON או צילום מסך) ושאלות מוטפסות: בחירה, כן/לא או ציון. מקבלים הסתברות לכל אפשרות במעבר אחד, בלי יצירת טקסט. הפורמט הוא של System One, שהוצג עם Jev של TypeSafe, ולכן לקוחות קיימים צריכים רק base URL אחר. אתמול כתבנו על Strands Decider; כאן החידוש הוא ריצה מקומית אחידה עם llama serve -hf ggml-org/Kev-4B-GGUF.

אילו מודלים ובאילו תנאים

בטבלה: Julia-1 (144M, 50+ שפות, Apache 2.0, כ-3ms), Laya (421M, אנגלית), Kev-4B ו-lev (4B, אנגלית, Apache 2.0) ו-OpenJev (27B, תמונות, שש שפות, רישיון CC BY-NC 4.0, כלומר לא לשימוש מסחרי). המהירויות הן חציון לשאלה אחת על כרטיס NVIDIA RTX PRO 6000, ולא על מחשב רגיל. הצוות כתב ש-Cloudflare Clef יתווסף בהמשך.

העצות בפוסט שוות קריאה: תאר כל אפשרות במילים, כי Julia-1 ניתב "חויבתי פעמיים" ל-shipping עם תוויות חשופות ול-billing (0.99) עם תיאורים; את סף הביטחון בוחרים לכל מודל בנפרד (פנייה עמומה קיבלה 0.25 ב-Julia-1 ו-0.80 ב-Kev-4B); ומודלים שונים מחשבים את ה-state פעם אחת ושאלות בחבילה. בכרטיס של Julia-1 הדיוק הוא 71.33% ב-choice על 600 מקרים ו-71.5% ב-MASSIVE על 52 locales, מדידות של היוצרים. לא אימתתי שעברית נכללת בשפות שנבדקו.

החיבור אליך: זה הניסוי שהשארנו פתוח אתמול. הריץ Julia-1 ו-Kev-4B על 100 הודעות בעברית של מענה (שאלות כמו כוונה, דחיפות, צורך באדם) והשווה לתשובה של ה-LLM הנוכחי לפי טווחי ביטחון. אם ב-podcasto יש שלב כן/לא על פריט, אותו ניסוי נותן סף. ב-dorgames כדאי לנסות רק אם יש החלטת משחק שחוזרת הרבה. אם הדיוק בעברית חלש, זו תוצאה שימושית: סימן שצריך לנסות מודל גדול יותר או להישאר עם LLM.

03Supabase Select: שרת MCP לאפליקציה, סכמה בקוד ו-Compute+

מה הוכרז

ב-Supabase Select (2.10) הוכרזו כלים שבהם סוכן הקוד מגדיר ומריץ את הבקאנד מתוך הריפו. Declarative Schemas 2.0: הסוכן עורך קבצי SQL ב-supabase/schemas/*.sql, והכלי החדש pg-delta מחשב את המיגרציה. פרויקטים חדשים מ-supabase init משתמשים בו כברירת מחדל, וקיימים מפעילים ב-config.toml. Config בקוד: הגדרות כמו auth providers ומגבלות API יושבות ב-config.toml, ו-supabase config pull מחזיר שינוי שנעשה בדשבורד. סביבה מקומית: Supabase יכולה לרוץ כתהליכים מקומיים בלי Docker, כולל sandbox של Claude Code, Codex ו-CI, ואפשר להריץ כמה מופעים, אחד לכל תיקייה. זה alpha וכבוי כברירת מחדל.

שרת MCP לאפליקציה שלך: פקודת npx shadcn@latest add @supabase/mcp-server מוסיפה Edge Function עם אימות, שמגיש כלים לסוכנים של המשתמשים שלך (Claude, ChatGPT, Cursor). המשתמש מתחבר כרגיל, והסוכן שלו רואה רק מה ש-RLS מאפשר לו. הקוד שלך, ואתה מוסיף כלים. הוא נפרד משרת ה-MCP הרשמי של Supabase שעוזר לבנות את האפליקציה. הוא דורש asymmetric signing keys והפעלת Supabase Auth OAuth server. Supabase Compute: שירותים ארוכי חיים בלי מגבלת זמן, עם Linux מלא, ב-config.toml, ו-supabase compute deploy. זה private alpha עם רשימת המתנה.

מה עוד לא מוכן

Compute ב-private alpha והסביבה המקומית ב-alpha וכבויה כברירת מחדל. הפוסט לא כולל מדדים או השוואת עלות. ההבטחה שהסוכן רואה רק מה שמותר תלויה בכך שה-RLS שלך מוגדר נכון ושהכלים שאתה מוסיף לא עוקפים אותו.

החיבור אליך: לאפליקציות על Supabase (בדוק ב-config של כל אחת) הכי מעניין ניסוי קטן על Declarative Schemas בפרויקט אחד שאינו production: האם הסוכן מצליח לשנות סכמה דרך קובץ SQL ולקבל מיגרציה נכונה. אם מענה או podcasto רוצות שסוכן של משתמש יפעל בתוך האפליקציה, MCP עם RLS הוא מבנה נקי יותר מהוספת מפתח שירות, אבל בדוק לפני כן שה-policies באמת מכסות כל טבלה שהכלי נוגע בה.
