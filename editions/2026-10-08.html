01Haiku 5.5: זול למשימות קצרות, לא החלפה עיוורת של המודל+

מה הושק

Anthropic השיקה ב-7.10 את claude-haiku-5-5: חלון של מיליון טוקנים, עד 128K פלט, adaptive thinking עם effort, והכוונה למשימות כמו סיווג, חילוץ, ניתוב ותתי-משימות. זמינות ב-Claude API, AWS, Google Cloud ו-Microsoft Foundry. גם GitHub הודיעה ב-7.10 ב-20:12 UTC על GA ב-Copilot במנויים בתשלום, בגלגול הדרגתי.

המחיר, עם האותיות הקטנות

ב-Claude API, לפרומפט עד 100,000 טוקנים: $0.10 לקלט ו-$0.50 לפלט למיליון טוקנים. מעל הסף: $0.50 ו-$2.50. קריאת cache עולה $0.01 או $0.05 בהתאמה. אלה תעריפי API, לא הבטחה לאותו חיוב בכל ספק. טענת "90% פחות" נכונה לתעריף בקשות מתחת לסף מול Haiku 4.5; מעליו מדובר ב-50%. Anthropic מעריכה חיסכון ממוצע של כ-75%, תוך התחשבות בשימוש בטוקנים.

אותו טקסט נספר ככ-30% יותר טוקנים מה-tokenizer של Haiku 4.5, לפי התיעוד. לכן צריך למדוד מחדש גם סף 100K, גם תקציב פלט וגם עלות למשימה. באותה הכרזה, מחיר קריאת cache של Sonnet 5.5 ירד מ-$0.20 ל-$0.10 למיליון טוקנים; "כ-20% חיסכון למשימה" הוא אומדן הספק שתלוי ביחס ה-cache שלך.

קרדיט API חודשי, לא קרדיט Claude Code

באותה השקה הוכרזו credits מתגלגלים למנויי Max ו-Team: $100 ל-Max 5x, $200 ל-Max 20x; ב-Team $20 לכל Standard seat ו-$100 לכל Premium seat, עד $500 משותפים. Pro, Free ו-Enterprise אינם זכאים. צריך מנוי פעיל שבעה ימים ולקשר ארגון Console אחד; אי אפשר להחליף את הארגון לבד. הקרדיט לא נצבר לחודש הבא, אינו חל על Claude Code אינטראקטיבי או על Bedrock/Vertex/Foundry. אם יש יתרה שנרכשה או auto-reload, השימוש ממשיך עליה לאחר שה-credit נגמר. הגלגול נמשך כמה ימים. לא בדקתי את המנוי שלך, ולא כדאי לקנות מנוי רק בגלל ההכרזה.

מה ישבור אינטגרציה ישנה

זה אינו רק שינוי model ID. מדריך ההגירה אומר להסיר temperature, top_p ו-top_k; להחליף thinking עם budget_tokens ב-adaptive; לא לסיים messages ב-assistant prefill; ולבחור content blocks לפי type ולא להניח שהראשון הוא טקסט. Thinking נספר בתוך max_tokens, ולכן תקציב קטן יכול להיגמר לפני שמתקבל טקסט. יש גם stop_reason: refusal ללא fallback שרת, ומגבלות על replay של thinking בין חשבונות ועל שינוי turns קודמים.

מה לא להסיק מהבנצ'מרקים

הנתונים בהכרזה הם של Anthropic ושל לקוחות שהיא מצטטת, לא בדיקה שלי. ב-Terminal-Bench 4.0 היא מפרסמת 39.2% ל-Haiku מול 70.6% ל-Sonnet 5.5. גם הספק אומר שהמודלים הגדולים עדיפים לקוד מורכב. חלון 1M אינו הוכחה לאמינות על מסמך ארוך או על עברית.

החיבור אליך: במענה וב-podcasto, התחל מניסוי מבודד של classification או extraction, לא מהחלפת הכותב או השופט בבת אחת. השווה דיוק בעברית, זמן ועלות לכל פלט שעבר validation. במערכת עם registry, הגדר יכולות ופרמטרים לפי המודל ולא רק provider: אחרת sampling או prefill ישנים עלולים להחזיר 400. אין כאן טענה ש-Haiku כבר מחובר לפרויקטים שלך.

02Microsoft Execution Containers ב-GA: לא כל כלי של הסוכן נמצא באותו sandbox+

מה חדש

Microsoft הכריזה ב-7.10 ב-18:00 UTC על GA של MXC, שכבת execution עם policy שמגדירה קבצים, רשת, תהליך וממשק משתמש. היישום בוחר backend בהתאם למערכת: ProcessContainer ב-Windows, Seatbelt ב-macOS ו-Bubblewrap ב-Linux. session container עם desktop נפרד הוא Windows בלבד; MicroVM מוגדר experimental במאמר. ב-README העדכני יש SDKs ל-Rust, .NET ו-Node, לצד schema משותף.

גבול האבטחה אינו כל הסשן

במאמר ההטמעה ב-Copilot, Microsoft מדייקת: כאשר sandboxing מופעל, פקודות shell, שרתי MCP מקומיים ו-language servers רצים בגבול תהליך. כלי הקבצים המובנים רצים בתוך Copilot עצמו, עם בדיקת policy ב-harness ולא בידוד child process של מערכת ההפעלה. שרתי MCP מרוחקים מחוץ ל-sandbox המקומי, ומדיניות החיבור נבדקת בתהליך. לכן "יש sandbox" לא אומר שכל נתיב קריאה או כתיבה נאכף באותה שכבה.

ללמוד policy בלי לבטל את ההגנה

במאמר ההשקה יש שלושה מצבים: Enforcement חוסם; Learning חוסם וגם מתעד את הגישה שלא הותרה; Permissive מתעד אבל מאפשר. דוחות הפעילות האלה מתוארים עבור process containers ב-Windows בלבד. ב-README החי יש אזהרה נוספת: --audit מכבה את אבטחת ה-sandbox למשימה, ואין להשתמש בו להרצת קוד לא מהימן. חשוב לא לבלבל בין איסוף מידע על חסימות לבין מצב שמאפשר אותן.

מה זמין ומה עדיין הבטחה

Microsoft מונה Copilot, Codex וכלים נוספים כתומכים; תמיכת Claude Code מתוארת כעתידית. גם ניהול דרך Intune וייחוס סוכנים דרך Entra/Agent 365 מתוארים כ-coming soon, לא כחלק שכבר עובד בכל מכשיר. זמינות ואכיפה תלויות backend, גרסת OS וה-policy. לא התקנתי ולא בדקתי עקיפה של גבולות.

החיבור אליך: אם אתה מריץ סוכן קוד על מענה, podcasto או dorgames, מפת הרשאות טובה מתחילה ברשימת מסלולים: shell, כלי קבצים, MCP מקומי, MCP מרוחק. הגדר ריפו לכתיבה, configuration לקריאה ונתוני משתמש מחוץ לתחום, ובדוק שכל מסלול באמת מכבד את זה. זו שיטת בדיקה שאפשר לקחת גם בלי לאמץ MXC.

03Claude Code 2.1.293: compaction יותר עקבי, אבל תיקון cloud wakeup חזר לאחור+

מה תוקן

הגרסה פורסמה ב-7.10 ב-18:10 UTC. תוקן מצב שבו Claude התייחס לא נכון לפעולות האחרונות סביב compaction, חזר בו או עשה שוב עבודה שכבר הסתיימה. תוקנה גם דליפת זיכרון בחיבור HTTP MCP ששמר כל בקשה עד סגירת החיבור, והודעה שנשלחה תוך עבודה ונעלמה במעבר הסשן לרקע.

כללים scoped לנתיב ו-CLAUDE.md מקונן נטענים כעת גם כשקוראים קובץ עם cat, head, tail, sed או grep דרך Bash, ולא רק דרך Read. בנוסף, hooks של mods על classic.* לא מדולגים בזמן restart של worker; ותהליכי hook/status line ב-Windows כבר אינם מפסיקים תהליך לא קשור שקיבל אותו process ID.

ה-rollback שחשוב לדעת עליו

ה-release notes אומרים במפורש: בוטל תיקון 2.1.290 לסשני ענן שנשארו ישנים אחרי restart של container שאיבד wakeup של loop או משימה מתוזמנת. במצב הזה Claude כבר לא מקבל הודעה והסשן נשאר ישן. זה מקרה ענן מסוים, לא הודעה שכל תיקוני המשימות של 2.1.292 בוטלו. אין ב-notes הסבר לסיבת ה-rollback או מועד לתיקון חלופי.

גם ניסוח deny ב-auto mode מ-2.1.281 הוחזר לאחור. זו סיבה לא להסתמך על הניסוח שהמודל רואה במקום על enforcement בפועל.

החיבור אליך: בסשן ארוך על podcasto או מענה, אל תסתפק בסיכום compaction כדי לדעת מה כבר נעשה: בדוק commit, קובץ ותוצאת test לפני retry של שינוי. ואם יש לך loop בענן שהמשך עבודתו חשוב, בדוק שהוא פעיל אחרי restart; ה-release החדש אינו מבטיח שהמקרה הזה התאושש. לא בדקתי אם אתה משתמש במסלול הענן הזה.

הסתייגות

קראתי את release notes המלאים; לא הרצתי 2.1.293 ולא שחזרתי את התקלות. הוספת Haiku בגרסה אינה אות רביעי נפרד, אלא חלק מההשקה בפריט הראשון.

מה לקחת ליום העבודה

מדוד משימה קטנה עם מודל זול לפני מעבר רחב; צייר את גבולות הכלים לפני שאתה סומך על sandbox; ובדוק שהמשימה נשמרה אחרי compaction או restart לפני שאתה מריץ אותה שוב.

הסריקה נשענת על מקורות מ-7.10, בחלון 24 שעות ואחרי batch 7.10 06:55 IDT. נפסלו כישנים למרות סיקור מ-7.10: Mistral Large 4 (מקור 6.10 12:00 UTC), GitHub stacked PRs (6.10 20:16 UTC), Claude ל-Google Workspace (6.10 במקור הרשמי). אלפות Codex ותיקוני Copilot קטנים לא נוספו כדי למלא מקום. Qdrant ללא release חדש.

קשרי הפרויקטים הם הצעות בדיקה בלבד. לא הוחלף מודל, לא הותקן sandbox ולא הופק פרק.
