01Qdrant 1.19.2: תיקון ל"אפס תוצאות" עם פילטר, ו-upsert דליל מהיר יותר+

מה יצא

גרסה 1.19.2 פורסמה ב-5.10 ב-14:16 UTC (הקודמת, 1.19.1, מ-4.9). ה-changelog ארוך, ואלה החלקים שנוגעים לשימוש יומיומי:

נכונות חיפוש: תיקון לחיפוש שהחזיר אפס תוצאות כשנקודת הכניסה של גרף ה-HNSW לא עומדת בפילטר (PR 10903); תיקון להוספת named multivector לקולקציה שכבר מאונדקסת, שהפילה את החיפוש (10870); תיקון ל-group_by על נתיב עם אינדקס מערך (10897); ושני תיקונים ל-MMR: pagination עם offset, ומועמדים שלא היו ממוינים לפי מרחק לפני המיזוג, מה שפגע בדיוק (10567, 10878).

שלמות נתונים: מניעת "write tearing" בכל אחסוני Gridstore, שלפי ה-changelog עלול היה להשחית אחסון (10837), ותיקון לאינדקס payload שלא נטען אחרי כתיבה קטועה ויצר crash loop (10812).

ביצועים ותפעול: upsert של וקטורים דלילים לא כותב מחדש את כל ה-posting list בכל פעם ("משמעותית מהיר יותר", 10682); proxy segments שומרים מצב, מה שמונע WAL תקוע וזמני התאוששות ארוכים בהפעלה מחדש; מנעול הקולקציות לא נשמר בזמן Raft snapshot; חישוב BM25 הועבר לthread חוסם כדי לא לתקוע את ה-runtime; תמיכה ב-GCS וב-Azure Blob לסנאפשוטים; ואזהרה בהפעלה כשלא הוגדר API key.

הסתייגויות

קראתי את ה-changelog של ה-release ולא את ה-PRs עצמם, ולא הרצתי את הגרסה. "משמעותית מהיר יותר" הוא ניסוח של Qdrant בלי מספרים. לא כתוב אילו גרסאות קודמות הושפעו מכל באג, ולכן אי אפשר לדעת מה-release לבדו אם הקולקציות שלך נתקלו בו.

החיבור אליך: אם יש לך קולקציה ב-Qdrant שמסוננת לפי payload (למשל לפי שפה או משתמש), התיקון של "אפס תוצאות" הוא מסוג הבאגים שנראים כמו "אין תוצאות רלוונטיות" ולא כמו שגיאה. בדיקה זולה לפני עדכון: הרץ שאילתה מוכרת עם פילטר צר על הגרסה הנוכחית וקבע שורת ביטחון שמוצאת פריט שאתה יודע שקיים; אחרי העדכון הרץ אותה שוב. אם אתה מחזיק Qdrant בענן מנוהל, בדוק איזו גרסה רצה אצלך לפני שמניחים שהתיקון כבר שם. אני לא יודע איך הקולקציות שלך בנויות, ולכן זו בדיקה ולא המלצה לעדכן.

02Claude Code 2.1.290: הוקים ל-mods, משימות מתוזמנות שחוזרות אחרי compaction+

מה יצא

גרסה 2.1.290 פורסמה ב-5.10 ב-23:33 UTC, אחרי 2.1.289 מלילה קודם. ה-release notes ארוכים; אלה החלקים הרלוונטיים:

mods והוקים של plugins: ל-hook turn.step נוסף serverToolUses, קריאות הכלים שה-API הריץ בעצמו (ה-advisor), עם מזהה, שם, קלט וזמני התחלה וסיום. ל-tool.check נוסף agentId, כך שהוק יכול להבדיל בין בדיקת הרשאה של subagent לשל הסשן הראשי, ושדה ceiling שמציין איזה אישור הארגון דורש לכלי. claude plugin validate מציג עכשיו לכל הוק בנקודת gating אם יש לו .catch.

CLI: claude attach <name> ו-claude logs <name> מקבלים חלק משם הסשן במקום מזהה; פקודה חדשה /claude-api managed-agents-onboard שמקימה את תבנית Managed Agents כקבצי ant apply; ואזהרות ב-/status כשהגדרות מנוהלות מתעלמות ממסלולי allowRead או דומיינים שהגדרת ב-sandbox.

תיקונים: משימות מתוזמנות (/loop עם מרווח, תזכורות) שלא חזרו ב-resume אחרי compaction, ושרצו פעם נוספת בכל resume, respawn או fork; WebFetch שזרק בשקט טקסט אחרי 100,000 תווים (עכשיו אומר כמה לא נקרא ומקבל offset); הרצה headless עם --json-schema שהסתיימה בשגיאה אחרי שהפלט המובנה כבר נמסר; מצב plan שבו מסווג ה-auto mode אישר כלי connector שאינו קריאה בלבד; וקובץ CLAUDE.md או כלל שהיה symlink מחוץ לתיקיות העבודה ונטען למרות blockReadsOutsideWorkingDirectories או כלל deny על Read.

הסתייגויות

רק ה-release notes נקראו; לא הרצתי את הגרסה. הרשימה בפועל כוללת עוד עשרות תיקונים (Windows, Remote Control, ultrareview) שלא פירטתי. לגבי ההוקים: ה-notes לא מסבירים מתי נכנסו הממשקים הקודמים של mods, ולכן אם לא כתבת mod בעצמך, החלק הזה לא נוגע אליך.

החיבור אליך: שלושה תיקונים נוגעים לדרך העבודה שלך ביום-יום. אם השתמשת ב-/loop או בתזכורות בסשנים ארוכים ב-Claude Code על podcasto או מענה, ייתכן שמשימה "נעלמה" אחרי compaction; מ-2.1.290 זה אמור להיות מתוקן, אבל רק לגבי compaction שנעשה מהגרסה הזו. ה-notes מציינים זאת במפורש. שנית, WebFetch כבר לא קוצץ בשקט: כשאתה נותן לסוכן לקרוא דף ארוך, הוא יודע עכשיו שחלק לא נקרא. שלישית, התיקון ל-symlink מוסיף שכבה לבדיקה שהצעתי אתמול: אם יש לך CLAUDE.md או AGENTS.md עם symlink מחוץ לפרויקט, בדוק בתיקייה זמנית שהוא לא נטען.

03Copilot CLI 1.0.92: sandbox שלא מחזיק GITHUB_TOKEN, ו-MCP שמתאושש בתוך אותו turn+

מה יצא

גרסה יציבה 1.0.92 של GitHub Copilot CLI פורסמה ב-5.10 ב-19:42 UTC, אחרי כמה גרסאות pre-release. מהרשימה:

sandbox: קונכיות ב-sandbox לא מקבלות יותר את GITHUB_TOKEN שבסביבה אלא אם הוגדר במפורש; סקריפטים שמריצים Git ב-sandbox מאומתים עם credentials מוסווים ושכתוב SSH; פקודות חיפוש לא מבקשות bypass כשכבר ניתנה גישה; uv ו-pnpm רצים ב-sandbox בלי שגיאות הרשאה על cache או lock-file; ופרומפט bypass לרשת מופיע בכל פעם שה-proxy חוסם יעד.

MCP: שרתי MCP מוגנים ב-Entra מחדשים access token בשקט; חיבורי HTTP+SSE ישנים לא נתקעים אם POST לא אושר, והאישור מוגבל ל-timeout של השרת; חיבור מחדש לשרת Streamable HTTP אחרי שהסשן פג; כלים ממשיכים לעבוד אחרי OAuth reauthentication כשהגדרות הכלים לא השתנו; ו-MCP מתאושש באותו turn כשהוראות השרת משתנות.

חדש: תת-פקודות copilot config (רשימה, קריאה, הגדרה, הסרה) ובורר סביבה Ctrl+E לפני שיחה, למעבר בין הרצה מקומית לענן. בנוסף: הודעה לסוכן רקע שרץ מכוונת את ה-turn הפעיל שלו, ו-compaction שומר את הפרומפט האחרון כשבקשה חורגת מהקשר.

הסתייגויות

רק הרשימה ב-release נקראה, בלי להריץ. "חדש" כאן הוא של Copilot CLI: דברים כמו config ו-sandbox קיימים בכלים אחרים. אין ב-notes מידע על כך אם הטוקן דלף בפועל בגרסאות קודמות או רק היה חשוף.

החיבור אליך: אין לי ראיה שאתה משתמש ב-Copilot CLI, ולכן הנקודה שכדאי לקחת היא עיקרון, לא כלי: קונכיית sandbox של סוכן לא צריכה לרשת את הטוקנים של הסביבה שלך כברירת מחדל. אצלך זה נכון גם ל-Claude Code ול-Codex: בדוק מה מוגדר ב-env כשהסוכן מריץ פקודת shell (env | grep -i token בתיקייה זמנית), ובעיקר איזה טוקן GitHub אתה נותן. טוקן עם הרשאת push ל-repo אחד בלבד עדיף על טוקן רחב. שרתי MCP שנתקעים או פוקעים באמצע סשן הם גם סיבה טובה לוודא ש-podcasto MCP מחזיר שגיאה ברורה ולא נתקע.
