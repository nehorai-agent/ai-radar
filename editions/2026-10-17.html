01Claude Code 2.1.302: סוכן-המשנה מקבל בירושה את כל השיחה+

מה הגיע בלילה

הגרסה היציבה פורסמה ב-16.10 ב-23:53:06 בישראל (Agent SDK ב-TS פורסם במקביל). מעבר לרשימת תיקונים ארוכה, ארבעה שינויי התנהגות בולטים: fork subagents הופכים לברירת מחדל בכל מקום, ברירת ההרשאות בסשנים אוטומטיים מתהדקת, אפשר לבחור מודל למסווג ההרשאות, ותוקן כשל שרשרת ב-MCP.

ההורשה שהפכה לברירת מחדל

fork subagent אינו סוכן רגיל: לפי התיעוד, הוא יורש את כל הקונטקסט של השיחה ההורה, את מאגר הכלים המדויק ואת אותו מודל, בעוד סוכן-משנה רגיל מתחיל נקי ומקבל רק את ה-prompt שהועבר בקריאה. עד עכשיו fork mode היה דולק כברירת מחדל רק בטרמינל האינטראקטיבי; ב-2.1.302 הוא נדלק גם ב-claude -p, ב-Agent SDK, באפליקציית הדסקטופ וב-VS Code, בדיוק המקומות שבהם רצות שרשרות אוטומטיות.

המשמעות הפרקטית: כל קריאת Agent ב-pipeline הלא-אינטראקטיבי שולחת עכשיו את תמליל השיחה המלא לסוכן-המשנה, אלא אם מגדירים subagent_type מפורש או מכבים עם CLAUDE_CODE_FORK_SUBAGENT=0. גודל הקונטקסט, העלות לקריאה ופרופיל ה-prompt cache משתנים עם עדכון גרסה, בלי שינוי קוד אצל המשתמש. גם חשיפת מידע משתנה: סוכן-משנה שקיבל רק הנחיה ממוקדת רואה כעת כל מה שההורה ראה. שרת MCP שמופעל דרך claude mcp serve לעולם אינו מציע forks.

ברירת הרשאות מתהדקת, והמסווג ניתן לבחירה

סשן claude -p או Agent SDK ללא permission mode מפורש מתחיל עכשיו במצב default - כלומר שואל - כשהספק הוא צד שלישי, כשהטלמטריה כבויה או בהתקנה חדשה. --permission-mode auto עדיין כופה auto. הכיוון ברור: מצב ללא-פיקוח דורש opt-in מפורש.

משתנה חדש, CLAUDE_CODE_AUTO_MODE_MODEL, בוחר באיזה מודל משתמש מסווג ה-auto mode בצד הלקוח - זה שמחליט אילו פעולות מאושרות אוטומטית. הוא אינו משנה את מודל ה-auto בצד השרת. ובצד השרת יש שינוי כיוון מעניין: שיחה ארוכה מדי לבדיקת הבטיחות עוברת כעת compaction, במקום שכל קריאת כלי נבדקת תידחה. מה-fail-closed שהשבית את הסשן, לניסיון להתכווץ ולהמשיך.

12 hooks במקביל, ותיקון שרשרת ב-MCP

hooks מאותו אירוע רצים מעתה עד 12 במקביל; השאר ממתינים בתור. מי שבנה שרשרת בדיקות כבדה על PreToolUse ירגיש את השינוי בתזמון, לא בתוצאה.

ותיקון שמחבר ישירות לאתמול: שרת MCP שמנהל משא ומתן על פרוטוקול 2026-07-28 אך משמיט את השדות resultType, ttlMs או cacheScope גרם ללקוח להציג אפס כלים או להכשיל כל קריאה. זה בדיוק סוג הבאג שיכול לרוקן שרת MCP מכולם בלי שגיאה מובנת, ורלוונטי לכל שרת MCP שחיברתם אתמול או מחר.

עוד שכדאי לדעת

כלי ה-Read מסרב כעת לטעון מקור תמונה מעל 128MB, ולא קורא לזיכרון במלואו pipe או device שנקרא בשם של תמונה. תוקנו פגיעות prompt cache כשכלי שנוסף באמצע שיחה נטען מחדש דרך ToolSearch או אחרי compaction. נוסף מתג Idle compaction ב-/config. ושולבה הודעה ש-Claude Design העצמאי (claude.ai/design) נסגר עד 14.12.2026.

חיבור אפשרי למענה, Podcasto ו-dorgames: אם אחד מהפרויקטים מריץ סוכנים דרך Agent SDK או claude -p, עדכון המינור הזה שינה גם את עלות סוכן-המשנה וגם את ברירת ההרשאות. כדאי לבדוק נעילת גרסה, הגדרת subagent_type מפורשת, והאם --permission-mode מוגדר במפורש שם שצריך auto. זו הצעת בדיקה, לא דיווח על תקלה אצלך.

02Cursor: סביבת הסוכן הופכת ל-API, והתוצר לקישור+

מה פורסם

רשומת changelog מתוארכת 16.10 (Cursor מסמנת תאריך בלבד, בלי שעה מדויקת). שלושה חלקים: סוכני ענן בונים canvases אינטראקטיביים כחלק מהריצה, Environments API יוצא לבטא, וסביבות ענן תומכות עכשיו בעד 300 ריפוזיטוריז עם טעינה מהירה פי 5 לסביבות גדולות. כיסוי אחד ציטט "500 ריפוזיטוריז"; במקור הראשוני כתוב 300, והמקור קובע.

קנבס כתוצר, לא כצ'אט

קנבס הוא תוצר אינטראקטיבי שהסוכן בונה - דוח, דשבורד או ממשק קטן. שיתוף קנבס אינו חדש בפני עצמו (הופיע כבר במאי), והחדש הוא שסוכן הענן מייצר אותו במהלך העבודה. הפרסום נעשה מכפתור Publish ב-toolbar: הקישור מציג snapshot חי, לקריאה בלבד, ופתוח רק לחברי הצוות - Cursor בודקת גם חברות בצוות וגם הרשאת ריפו של הצופה. שיתוף דורש מסלול בתשלום ו-privacy mode שמאפשר אחסון נתונים, ואדמין יכול לכבות את התכונה לכל הארגון. כלומר: תוצר הסוכן יוצא מהתמליל ומקבל בקרת גישה משלו.

הסביבה הופכת לקוד שאפשר לנהל

ה-Environments API החדש (חלק מ-Cloud Agents API v1, בבטא ציבורי) מאפשר ליצור, לקרוא ולעדכן סביבות ענן שמורות: אילו ריפוזיטוריז נשכפלים ומה ה-environment.json שרץ עליהן. הסכימה זהה לקובץ .cursor/environment.json בריפו, וקונפיגורציה שגויה מחזירה 400 validation_error. סדר ההתאמה נשאר: קודם קובץ בריפו, אחר כך סביבה אישית שמורה, אחר כך סביבת צוות. ריצה על מכונות self-hosted קוראת רק את רשימת הריפוזיטוריז ומתעלמת מ-environment.json.

פרט בטא שכדאי לתפוס: שדה envVars - משתני סביבה מוצפנים לסשן - נפרס בהדרגה. אם הוא עדיין לא פעיל בחשבון, הבקשה לא נכשלת; השדה פשוט מתעלם בשקט. לפני שמסתמכים על סודות שהוזרקו דרך ה-API, בודקים שהם באמת נוכחים בסביבה.

למה זה אות

שני החלקים מספרים אותו סיפור משני הכיוונים: מצד אחד, הסביבה שבה הסוכן רץ הופכת לתשתית מנוהלת בקוד, משהו שאפשר לשכפל, לגרס ולתסרת. מצד שני, הפלט של הסוכן הופך לארטיפקט משותף עם הרשאות, לא עוד רשומת צ'אט שמעתיקים ממנה. מי שמתכנן עבודת סוכנים רצינית צריך את שני הצדדים: סביבה ניתנת לשחזור ותוצר ניתן לשיתוף.

חיבור אפשרי למענה, Podcasto ו-dorgames: דף הרדאר הזה הוא בדיוק הדפוס של ארטיפקט שסוכן מייצר ומשתף בקישור. אם בעתיד תרצו סביבות פיתוח ניתנות לשחזור לסוכנים שעובדים על הפרויקטים, סביבה-כ-JSON דרך API היא הדפוס לחקור. אין כאן המלצה לעבור ל-Cursor או לשנות תשתית קיימת.
