1Claude Code: ה-sessions בענן יצאו מ-preview, עם קרדיט חד-פעמי+

מה השתנה

Cloud sessions של Claude Code יצאו מ-research preview והם זמינים באופן כללי. כל session רץ ב-VM מבודד בתשתית של Anthropic, מבצע clone לריפו מ-GitHub, מריץ פקודות ובדיקות וממשיך לעבוד גם כשהמחשב סגור. אפשר להתחיל מ-claude.ai/code, מלשונית Code באפליקציה, מהדסקטופ או עם claude --cloud. מנויי Pro קיימים מקבלים קרדיט חד-פעמי של ‎$100 ומנויי Max ‎$250. צריך לממש אותו עד 7 באוקטובר 23:59 PT (דרך /claim-credit או דף ה-claim), והוא פג ב-4 בנובמבר. הקרדיט מנוצל לפני מכסת המנוי, ואחריו ה-sessions חוזרים למכסה הרגילה.

למה זה שלך

ב-stack של podcasto (‏#152 ו-#153) ה-CI כמעט לא רץ, וכל ריצת tsc ו-vitest מלאה נעשתה ידנית. session בענן שמריץ את הבדיקות המלאות על ה-branch בזמן שאתה לא ליד המחשב הוא בדיוק המקום לנצל את הקרדיט, בלי לגעת במכסה של ה-sessions המקומיים. אם אתה על Pro או Max, שווה לממש לפני 7.10.

שני דברים שכדאי לדעת: ה-session מושך מ-GitHub את מה שנדחף, לכן צריך לעשות push לפני שמתחילים. קבצים שלא ב-git לא עוברים. וחשוב להבדיל בין הקרדיט החינמי הזה לבין usage credits בתשלום: אם הפעלת חיוב לפי צריכה, session ארוך בענן ימשיך לצרוך גם כשאתה לא מסתכל.

2SalesBleed: טופס ציבורי אחד, וסוכן Agentforce מדליף נתוני CRM בלי קליק+

מה קרה

חוקרי Zenity פרסמו שלוש חולשות ב-Salesforce Agentforce. תוקף משאיר prompt injection בטופס Web-to-Lead הציבורי, וההוראות מחכות עד שעובד מבקש מהסוכן "תבדוק את ה-leads האחרונים". אז הסוכן שולף שדות מטבלת Accounts, מדביק אותם כ-subdomain של דומיין של התוקף ומחזיר אותם בתג img. הדפדפן טוען את התמונה, והנתונים יוצאים דרך DNS. ה-Trusted URLs של Salesforce היו אמורים לחסום את זה, אבל לא זיהו TLD לא מוכר ונשברו מתווים מסוימים. אותה שרשרת עבדה גם דרך ה-unfurling של Slack. החולשה השלישית: הפעולה Reply to a Slack Thread שלחה הודעות בשם הסוכן בלי אישור ובלי לציין מי הפעיל אותה, כלומר ערוץ פישינג אנונימי.

למה זה שלך

Zenity מסכמים את זה בשלושה רכיבים: הסוכן קורא תוכן שמגיע מבחוץ, מציג לינקים או תמונות בחזרה, ויש לו גישה לנתונים רגישים. ב-podcasto המקורות שמשתמשים מכניסים הם בדיוק "תוכן מבחוץ", והשאלה שעלתה אתמול (טקסט תפעולי שנכנס ל-source והמודל פשוט ביצע) היא אותה בעיה בגרסה תמימה. במענה, כל מקום שבו תשובה מציגה markdown עם תמונות או לינקים שהמודל כתב הוא ערוץ יציאה פוטנציאלי.

בדיקה קונקרטית: לוודא שה-UI לא מרנדר img או לינקים שנוצרו על ידי המודל לדומיינים חיצוניים בלי allowlist, ושפעולות שכותבות החוצה דורשות אישור. Salesforce תיקנה את שלוש החולשות (אומת ב-21 בספטמבר). הדפוס עצמו לא ייחודי לה.

3Docker Cloud Sandboxes: אותו microVM לסוכן, עכשיו גם בענן+

מה יצא

Docker השיקה Cloud Sandboxes: אותו sandbox מבוסס microVM (kernel ו-Docker daemon משלו) שרץ עד היום על המחשב, עכשיו גם על compute של Docker. sbx move my-project --to cloud מעביר את מערכת הקבצים לצד השני, בשני הכיוונים. יש kits מוכנים ל-Claude Code, Codex, Copilot, Open Code ו-Hermes. יש gateway אחד ל-MCP servers שמוגדר פעם אחת לכל הסוכנים, ומדיניות רשת. הסודות נשמרים ב-proxy שמזריק אותם לכל בקשה, כך שהסוכן לא רואה את המפתח בכלל. התמחור הוא לפי שנייה: ‎$0.14 לשעה ב-Small (‏2 vCPU, ‏4GB), ‎$1.12 ב-XL. ברירת המחדל היא שעה, עד 24 שעות ל-session, ו-sandbox מושהה לא עולה כסף.

למה זה שלך

Hermes ברשימת ה-kits, וזה הפרויקט שיש לך בו עשר PRs ו-issues פתוחים. ה-proxy לסודות עונה בדיוק על הבעיה של טוקנים כמו ה-pk_ של podcasto MCP: מה שהסוכן לא מחזיק, prompt injection לא יכול לגנוב. וזה הצד השני של הפריט הראשון: Anthropic מריצה רק את Claude Code בענן שלה, Docker מציעה ענן אחד לכל סוכן, עם מודל שאתה מביא.

הסתייגות: כל הנתונים (ובהם "אף sandbox אחר לא עובד כך") הם מההכרזה של Docker. ניהול מרכזי ל-enterprise עוד "בקרוב". התמחור הוא על compute בלבד, ה-inference משולם בנפרד.

4Google Cloud API Gateway: הופכים REST קיים לכלי MCP מתוך ה-OpenAPI+

מה יצא

ב-Public Preview, ‏API Gateway של Google Cloud יכול לשמש שרת MCP מרוחק: מוסיפים x-google-api-management.mcp: true ל-spec של OpenAPI (‏3.0 או 3.1 בלבד), ובכל operation אפשר לתת שם ותיאור לכלי. אחרי deploy, ה-gateway מקבל JSON-RPC של MCP ב-/mcp, ממיר כל tools/call לבקשת REST רגילה ומפעיל עליה את האימות וה-quota הקיימים. כך אין שרת MCP נפרד שכותב מחדש את הלוגיקה.

למה זה שלך

ל-podcasto כבר יש endpoint של MCP שנכתב ידנית. שני דברים מהפוסט רלוונטיים גם בלי Google: (1) Google כותבת ש-tools/list פתוח כברירת מחדל, וזה מפרסם לכל אחד את שמות הכלים וה-schemas. כדאי לבדוק מה ה-endpoint שלך מחזיר בלי טוקן. (2) "התיאור הוא הסיגנל העיקרי שהמודל משתמש בו כדי להחליט מתי לקרוא לכלי", ולכן כדאי לכתוב מתי ולמה להשתמש, לא רק מה הכלי מחזיר. זה מתחבר לתקרת 2,048 התווים לתיאור שנוספה אתמול ב-Claude Code.

הסתייגות: זה Preview. OpenAPI 2.0 לא נתמך. מפתחות API לא מספיקים לאבטחת ה-discovery, צריך JWT.
