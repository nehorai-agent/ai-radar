Claude Code יבנה רק משחקים מקוריים, מכסות ChatGPT ו-Codex מתאחדות

Claude Code קיבל הוראת מערכת לבנות משחקים מקוריים בלבד - עם אישור Anthropic וסערה בקהילה; OpenAI מאחדת את מכסות השימוש של ChatGPT ו-Codex לבריכת טוקנים אחת מדצמבר; ו-MCP registry v1.8.7 עם JSON מוכן מראש ובנצ׳מרק כנה.

Anthropic מכוונת את Claude Code הרחק מחיקויי משחקים, OpenAI מאחדת את בריכת השימוש של ChatGPT ו-Codex.

יום ראשון עם שלושה כרטיסים, שניים מהם late catch מ-30.10 שבשלו לכדי סיפור רק בסוף השבוע: Claude Code קיבל הוראת מערכת מפורשת לבנות משחקים מקוריים בלבד - עם אישור רשמי של Anthropic וסערה בקהילת המשחקים; OpenAI הודיעה שמדצמבר המכסה של ChatGPT ו-Codex תהיה משותפת ונמדדת בטוקנים; ו-MCP registry v1.8.7 מוזכר בקצרה עם יחס כבוד למגבלות הבנצ'מרק שלו עצמו.

חיתוך הפרסום הקודם: 31.10 ב-06:58 בישראל. כרטיסים 01 ו-03 הם late catch מ-30.10 (בתוך 48 שעות מהאירוע שהפך אותם לסיפור, לפי כלל העדכון); כרטיס 02 עודכן ב-31.10. סוננו בין השאר: Bedrock AgentCore Runtime session endpoints (30.10, גבולי בחלון ושולי בערך), מדריך העלויות של Bedrock, GPT-6 Rosalind (מדעי החיים, גישה לארגונים מאושרים בלבד), הערכת Copilot של Microsoft Research על ארגונים סינתטיים, ו-Show HN שוליים (bootgpt, NES Contra).

מה זה ולמה כאן

late catch: השינוי עצמו נשלח ב-Claude Code 2.1.314 ב-30.10 וכמעט לא דווח אז; הוא התגלה על ידי משתמשים, אושר רשמית על ידי Anthropic, והפך לסיפור ראשי רק ב-30-31.10 (119 נקודות ב-HN ב-31.10). זה שינוי מדיניות חי בתוך הכלי שאתה עובד איתו יומיומית - ויש לו משמעות ישירה לכל מי שבונה משחקים עם סוכנים.

מה בדיוק נוסף

לפרומפט המערכת של Claude Code נוספה סקציה חדשה בשם original_games_guidance (בקוד הפנימי מסווגת תחת tengu_heron_brook). נוסח הכלל, כפי שצוטט מהכלי: Do build original games, games in a genre, and games from the user's own designs and assets. Do not build a recreation of a specific existing game, even if it is renamed or called original. שים לב לחדות: "גם אם שינית שם או קראת לזה מקורי" - הסינון הוא על השחזור עצמו, לא על ההצהרה.

האישור הרשמי וההקשר

אדי עוסמני מצוות Anthropic אישר ב-X: "הוספנו שני משפטים לפרומפט של Claude Code על Opus 5.5 כדי לכוון אותו הרחק משחזור משחק ספציפי של מישהו אחר, כי שימוש ב-Claude להפרת IP מנוגד למדיניות השימוש". הוא הדגיש שמשחקים מקוריים, משחקי ז'אנר ומשחקים מהעיצוב שלך אמורים להמשיך לעבוד, וביקש דיווח על סירובים שגויים. הרקע: שבועות של הצפת Steam במשחקים וייב-קודדים, אולפנים שביטלו דמויים פומביים מפחד ששכפול הקוד, ויכולות ה-reverse engineering החזקות של Opus 5.5. Valve, אגב, מסרבת לאסור כלי AI וממליצה למפתחים "להקשות על ההעתקה" דרך יצירתיות מתמשכת.

איך לקרוא את זה

זו הפעם הראשונה ש-Anthropic מטמיעה הגבלת תוכן סקטוריאלית ישירות בפרומפט של כלי הפיתוח - לא במדיניות בלבד, אלא בהתנהגות הדגם בזמן אמת. האתר שעוקב אחר דיפים של הפרומפט מסמן אי-ודאות: לא ברור אם הסקציה תמיד פעילה או ניתנת לכיבוי. ויש דיווחי משתמשים על חסימות רחבות מהמכוון - גבול ההפרדה בין "ז'אנר" ל"שחזור" ייקבע בפרקטיקה.

חיבור אפשרי לפרויקטים שלך: ל-dorgames זו בשורה דווקא: משחקים מקוריים מהעיצוב שלך אמורים להמשיך לעבוד בדיוק כרגיל, והכלל מגדיר במפורש את מה שמותר. אבל אם Claude Code מסרב למשימה לגיטימית על משחק משלך - זה בדיוק ה-false positive שעוסמני ביקש לשמוע עליו, ושווה לדווח. ובכיוון ההפוך: אם חשבת לבנות "פרוטוטייפ לימודי" של משחק קיים כדי ללמוד מכניקה, הכלי יסרב - תצטרך לנסח את זה כמכניקת ז'אנר עם עיצוב משלך מהשורה הראשונה.

מה זה ולמה כאן

עדכון בדף התמיכה הרשמי של OpenAI (עודכן ב-31.10): החל מדצמבר, מכסת השימוש של מנויי Plus, Pro ו-Business תהיה משותפת ל-ChatGPT ול-Codex. מי שמשתמש ב-Codex ככלי עבודה יומיומי מרגיש את זה ישירות בתכנון החודש.

מה משתנה בפועל

השימוש יימדד בטוקנים - מודלים מתקדמים ומשימות מורכבות צורכים יותר מהמכסה. צ'אט רגיל (Instant) לא יורד מהמכסה - רק העבודה האג'נטית. צריכה משולבת וזמני איפוס יוצגו ב-Settings → Usage. אם נגמרת המכסה: להמתין לאיפוס, לשדרג מסלול, או לקנות קרדיטים. OpenAI מסבירה שהמהלך חלק מהכנסת "היכולות האג'נטיות של Work" לתוך חוויית ChatGPT הראשית, ומבטיחה ש"רוב המשתמשים לא יצטרכו לחכות לאיפוס לעיתים קרובות יותר מהיום".

איך לקרוא את זה

איחוד המכסות הוא צעד מסחרי קלאסי: בריכה אחת הופכת את Codex למוצר מכירה נוסף על אותו מנוי, ומכשירה את הקרקע לתמחור מדורג לפי טוקנים. לשים לב לניסוח המדויק: "לא לחכות לאיפוס לעיתים קרובות יותר" - הבטחה מגובבת בכוונה. עדיין לא פורסם תאריך דצמבר מדויק ולא טבלת צריכה לפי מודל ומשימה - שני אלה יקבעו אם המעבר שקוף או מטריד.

חיבור אפשרי לפרויקטים שלך: אם סשנים ארוכים של Codex על מענה או dorgames מתחלקים היום במכסה נפרדת, מדצמבר הם מתחרים על אותה בריכה עם הצ'אט האג'נטי - שווה לעקוב אחרי צריכת הטוקנים החודשית שלך כבר עכשיו כדי לדעת אם המסלול הנוכחי יספיק. מדידה בטוקנים גם מחדדת את הערך של קונטקסט מצומצם: סשן ממוקד עם ריפו נקי יעלה פחות מאשר "תעבור על הכל".

03late catch, 30.10: MCP registry v1.8.7 - JSON מוכן מראש לרשימות, עם כנות נדירה על גבולות הבנצ'מרק+

מה זה ולמה כאן

late catch: שוחרר ב-30.10 וסונן אתמול כ-patch ביצועים; נכנס היום בגלל האיכות הטכנית של ה-release עצמו. שרת ה-registry של MCP הוא נקודת הכניסה שממנה לקוחות מושכים רשימות של שרתים - נתיב הקריאה החם ביותר שלו.

מה שוחרר

v1.8.7 מכינה את ה-JSON של עמודי הרישום מראש (prepared listing) במקום לפענח ולבנות מחדש את payloads השרתים בכל קריאת רשימה. הכבוי כברירת מחדל, עם backfill מוגבל ואפשרות rollback בדגל. שורות הרישום משחררות את חיבור ה-DB לפני עיבוד ה-JSON; ברירות מחדל ה-pool נשארו 60/10.

למה הכרטיס נכנס: המליצה על הכנות

המספרים המצורפים: 63% פחות זמן encoding ו-88% פחות allocations בבנצ'מרק encoding מקומי על רשומות פומביות שמורות. אבל היוצרים עצמם כותבים במפורש שאלו "תוצאות עלות encoding, לא הבטחת קיבולת שיא", ושה-replay ההיקפי ב-staging נותר לא חד-משמעי בגלל מיצוי פורטים בגנרטור העומס. זה סטנדרט דיווח שכדאי לדרוש מכל release עם מספרי ביצועים - כולל מהספקים הגדולים.

חיבור אפשרי לפרויקטים שלך: אם מענה או Podcasto יחשפו בעתיד רשומות דרך registry ציבורי, דפוס ה-prepared JSON (בניה מראש + שחרור חיבור לפני עיבוד) רלוונטי ישירות לנתיבי הרשימה הכבדים שלך - וזה דפוס שאפשר לאמץ גם בלי המוצר. השקיפות על מגבלות הבנצ'מרק היא דוגמה לשכפול בדיווחים שלך.
