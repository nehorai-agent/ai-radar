02Claude Code 2.1.312: הגנה מדריסת קבצי הקשר גדולים, תקרת hooks, ושינוי שקט ב-system prompt+

מה פורסם

v2.1.312 ב-27.10 ב-20:24 UTC, יום אחרי 2.1.311. גרסת אמצע עם תיקון בטיחותי אחד חשוב, שני שינויי ברירת-מחדל שכדאי לדעת, וערימת תיקוני VS Code ו-cloud sessions.

התיקון החשוב

Claude יכול היה לדרוס CLAUDE.md, קובץ rules או קובץ @-מצורף גדול מאוד בתת-תיקייה אחרי שראה רק את תחילתו. מעכשיו הכלי Write דורש מ-Claude לקרוא את כל הקובץ או לערוך במקום. בדיוק סוג הכשל שהורס שעות של תיעוד מצטבר בשקט.

שני שינויי התנהגות לשים לב

ב-Bedrock, Vertex, Foundry ו-Mantle, שמות מודלים ש-Claude Code לא מכיר (custom deployment names, inference profile ARNs) עוברים לsystem prompt הקצר גם כשהם מקדימים Sonnet או Haiku - CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0 מחזיר את המלא. ובאותו כיוון, החלפת מודל אוטומטית אחרי הודעה שסומנה (refusal fallback) חלה כעת גם על שמות לא מוכרים - CLAUDE_CODE_DISABLE_REFUSAL_FALLBACK=1 מכבה. מי שמריץ דרך gateways עם שמות פריסה משלו - שני השינויים נוגעים בך ישירות.

עוד

תקרה על hooks: עד 24 prompt/agent hooks במקביל לסשן (כולל sub-agents) ועד 12 שחיכו מעבר ל-timeout. Claude Code מפסיק לשלוח את אירוע ה-OTel claude_code.safety_event (נוסף רק ב-2.1.307). oidc.user_id_claim ב-gateway של Claude apps לזיהוי לפי claim שאינו sub (למשל oid של Entra). תוקן: managed settings ו-org policy לא נשלפו אחרי התחברות מתוך תוסף VS Code. שגיאות WebFetch בסשני ענן מסבירות עכשיו שה-host כנראה מחוץ לדומיינים המותרים - ושצריך לאשר אותו.

חיבור אפשרי לפרויקטים שלך: אם מענה או dorgames מריצים Claude Code מול Bedrock/Vertex עם שמות deployment משלהם - בדקו שה-system prompt הקצר לא משנה התנהגות שאתם סומכים עליה. ותיקון דריסת קבצי ההקשר רלוונטי לכל ריפו עם CLAUDE.md מפותח. זו שאלת בדיקה, לא דיווח על תצורה קיימת. הסתייגות: קראנו את רשימת הגרסה ולא הרצנו אותה.

03Copilot SDK מקבל אימות server-to-server: סוכנים עם זהות אפליקציה, בלי משתמש מחובר+

מה פורסם

ב-27.10 (public preview): שירותים וסוכנים שנבנו על GitHub Copilot SDK יכולים לבצע בקשות בשם ארגון - בלי להסתמך על credentials של משתמש מחובר.

איך זה עובד

נותנים ל-GitHub App הרשאת Copilot Requests (קריאה-בלבד) ברמת ארגון, מתקינים אותו על הארגון, ומעבירים ל-SDK installation access token קצר-חיים. השימוש מיוחס ומחויב לארגון הבעלים של ההתקנה, ומדיניות המודלים, התקציבים ובקרות ההוצאה של הארגון חלות כרגיל. בעלי הארגון רואים אילו apps מחוברים, מזהים שימוש של app בדוחות ה-CSV של AI usage דרך שדה app_client_id, וחוסמים בהשעיה או הסרה.

למה זה משנה

עד עכשיו אוטומציה על Copilot הייתה קשורה לזהות של מישהו - הטוקן שלו, המכסה שלו, הסשן שלו. identity בבעלות ה-workload עצמו הוא התנאי להרצת סוכנים בקנה מידה: CI שמריץ Copilot SDK, שירות פנימי שמשרת צוותים, בלי "חשבון הבוט של דני". בשילוב עם פירוק ה-metrics לפי client ממהדורת 25.10, הארגון רואה גם מי צורך וגם מי משלם.

חיבור אפשרי לפרויקטים שלך: אם במענה או dorgames יש (או יהיה) תהליך אוטומטי שמריץ Copilot SDK - אפליקציית סיכום PRs, בוט בדיקות, שירות פנימי - זו הדרך הנקייה: app עם הרשאת קריאה-בלבד במקום טוקן אישי של מפתח. זו הצעה, לא דיווח על תהליך קיים.

04late catch, 26.10: assisted permissions של Copilot ב-GA - LLM מאשר פעולות "בטוחות בבירור"+

מה זה ולמה כאן

late catch: פורסם ב-26.10 ולא נתפס בסריקות 26-27.10. צעד נוסף בהסרת האדם מלולאת האישורים - השבוע ב-GA.

מה זה

כש-Copilot מבקש רשות להריץ פקודה, לגשת לנתיב בקבצים או לפתוח URL, מודל שפה מסווג את הבקשה. בקשות שסווגו כ"בטוחות בבירור" ממשיכות אוטומטית; כל השאר דורשות אישור. זמין ב-Copilot CLI (/permissions ואז assisted), באפליקציית Copilot וב-VS Code.

בקרות ארגוניות

אדמינים יכולים לחסום את Allow All תוך השארת Assisted זמין (או לכבות Assisted בנפרד), ולקבוע את מצב ההרשאות ברירת-המחדל לסשנים חדשים; אם ברירת-המחדל אסורה במדיניות, הסשן נפתח באישור ידני.

איך לקרוא את זה

זו אותה שאלה ממהדורות 24-25.10 (פרצות ה-sandbox של Claude Code, תקרית AISI, הכילה של OpenAI) מהצד השני: אחרי שבונים גבולות, באים להוריד את חיכוך האישורים. הסיווג ב-LLM הוא לא הוכחת בטיחות - הוא שכבת נוחות. ההגנה האמיתית נשארת אותם allowlists, sandbox ו-blast radius מוגבל; ה-GA הזה שימושי בדיוק כשאלה כבר קיימים.

חיבור אפשרי לפרויקטים שלך: אם אתם שוקלים Assisted בסביבת העבודה על מענה או dorgames, הקריטריון הוא מה כבר מוגבל ברמת המערכת (הרשאות קבצים, רשת, secrets) - לא איכות הסיווג. זו שאלת בדיקה, לא דיווח על שימוש קיים.
