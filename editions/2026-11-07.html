מה זה ולמה כאן

פוסט מחקר של צוות ההנדסה של Anthropic (6.11) - אחד הטקסטים הפרקטיים ביותר שיצאו השנה על זיכרון לסוכנים. המסגרת: כמו ההיפוקמפ והנאוקורטקס, גם סוכן צריך שני מסלולים - לכידה בזמן-אמת (לוגים, תמלילים) וגיבוש לא-מקוון ("חלימה", בעקבות sleep-time compute של Letta ו-Berkeley): סשנים נפרדים שבהם הסוכן קורא את הלוגים, מתקן טעויות, מייצר פתקים ומבנה-זיכרון חדשים, ומחליט מה ייטען מראש לסשנים הבאים.

המספרים

ניסוי הוויקי: קורפוס של 350,000 קבצים פנימיים (~420M טוקנים, של Stainless), 25 שאלות הערכה. סוכני Opus 5 בנו ויקי ב"חלימה" - כל סשן כתב/תיקן עמודים, מיזג כפילויות ובדק טענות מול המקור. בין 2 ל-128 סשנים, הציון על ויקי-לבד עלה מ-13% ל-48% מהקריטריונים; ויקי + חיפוש התברג כשילוב הטוב ביותר (61%, מול 53% לחיפוש-לבד, ובחיסכון של ~20K טוקנים לשאלה). ניסוי פוקימון: Sonnet 3.7 כתב 413 קבצי-זיכרון ב-225 תיקיות (קובץ לכל קרב, חפץ ודמות) - והשיג תג אחד; Fable 5 כתב 9 קבצים בשתי תיקיות + global.md - והשיג ארבעה תגים. הצבירה הבלתי-מבחנת הזיקה: הרשומות התיישנו כל הזמן, והסוכן בזבז צעדים על ניהול הזיכרון במקום על המשחק. ושני פרטי-פרומפטינג חשובים: "רשום רק כשלונות" קיצץ את רוב הרווח מהזיכרון; ולומדים לסוכן לקרוא את הזיכרון ולבחון את התיאוריות שלו - כמעט הכפילו את הציון.

איך לקרוא את זה

הלקח המרכזי: מה לזכור חשוב מכמה לזכור. זיכרון טוב הוא תחזית על מה שהעתיד יצטרך - עובדות יציבות שהסביבה לא תגיד שוב (כללים שאומתו, מלכודות, הכרות), לא ארכיון של כל מה שקרה. ויש גם אישור נסיוני לתבנית שכבר עובדת אצלנו: עיבוד-לילי מצטבר על לוגים עדיף על כתיבת-זיכרון באמצע משימה.

חיבור אפשרי לפרויקטים שלך: לסוכני מענה ו-Podcasto: הפרד בין כתיבה בזמן-המשימה (לוג גולמי בלבד) לסשן "חלימה" לילי שמייצר פתקים מגובשים - ואל תאחסן דבר שאפשר לקרוא שוב מהקובץ עצמו. ובנה את הזיכרון כויקי עם קישורים + חיפוש, לא כתיקיית פתקים שטוחה; הקריטריון לשמירה: "האם הסביבה תגיד את זה שוב?"

מקורות: The components of agent memory - Anthropic (6.11)

026.11: AWS מריצה Claude Code כסוכן מרוחק על Bedrock AgentCore - microVM למשימה, טוקן GitHub ל-8 שעות, ו-PR טיוטה אלא אם האימות עבר+

מה זה ולמה כאן

מדריך-ארכיטקטורה מלא בבלוג ה-ML של AWS (6.11): הרחבת Claude Code לסשנים מרוחקים שרצים בענן, עם שכבת בקרות-אבטחה. זו לא הדגמת צעצוע אלא תכנון-ייצור עם החלטות ששווה להעתיק גם מחוץ ל-AWS.

הארכיטקטורה

כל ריפו רשום מקבל runtime משלו (אימג' ECR אחד עם Claude Code CLI, Agent SDK, git ו-make); כל משימה רצה ב-microVM נפרד בתוך VPC עם private endpoints בלבד - בלי credentials אחרים של AWS בקונטיינר. זרימת העבודה: תכנון עם Opus, כתיבת הקוד עם Sonnet, הרצת פקודות ה-setup/test של הריפו עצמו, סקירה חוזרת עם Opus - ועד שלושה נסיונות, כשהסקירה יכולה להחזיר לתכנון. בין משימות, AgentCore memory מחלצת "לקחים" פר-ריפו (למשל: שלב build עם דרישה נסתרת).

בקרות האבטחה

הסוכן אף פעם לא מחזיק credential ארוך-חיים של GitHub: AgentCore Identity מנפיק טוקן user-to-server ל-8 שעות שמתחדש אוטומטית, תקף רק לריפוס שהאפליקציה מותקנת עליהם, והקומיטים נכתבים תחת חשבון הבוט. כל פרומפט-משימה נסקר קודם ע"י Bedrock Guardrails (חסימת jailbreak, prompt injection וסודות; פרומפט חסום מחזיר PromptBlockedByGuardrail). והכלל החשוב מכל: ה-PR (מבראנץ' agent/<taskId>) מתעד את פקודת האימות, קוד-היציאה ומספר הנסיונות - נפתח כטיוטה אלא אם האימות עבר, והסוכן אף פעם לא ממזג.

חיבור אפשרי לפרויקטים שלך: גם בלי AgentCore, שלושה כללים לגנוב כבר השבוע לסוכני dorgames/מענה: פיצול plan-יקר/write-זול/review-יקר; טוקן-ריפו קצר-מועד בלבד; ו"טיוטה אלא אם האימות עבר + הסוכן לא ממזג". אם וכשמענה יצטרך סוכני-רקע על קוד לקוחות - זו תבנית הייחוס המלאה, כולל הלקחים פר-ריפו.

מקורות: AWS Machine Learning Blog (6.11)

036.11: Claude Code 2.1.319 - משימות MCP ברקע בטרמינל, deny-במקום-פרומפט ל-CI, ותיקון לשרתי MCP בלחיצת-יד ישנה+

מה זה ולמה כאן

שוחרר 6.11 ב-19:04 בישראל, יומיים אחרי 2.1.318. הגרסה עמוסה בשינויי auto mode ו-gateway, אבל שלושה דברים רלוונטיים במיוחד לבוני-סוכנים.

החדש

משימות MCP בטרמינל: כששרת MCP מריץ tool call כ-task, Claude Code מעביר אותו לרקע מיד ומודיע לקלוד כשהוא מסתיים - לא עוד תקיעת סשן על קריאת MCP ארוכה (ומי שרוצה את ההתנהגות הישנה: CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND). permissions.denyInsteadOfPrompting: קריאה שהייתה מחכה לפרומפט הרשאה נדחית והתור ממשיך - בטרמינל, סאב-אייג'נטים ו-teammates; זה המצב הנכון לריצות CI ללא-נוכח. ו-/claude-api latency-optimize סורק את קוד ה-API שלך, מוצא איפה משתמשים מחכים, ומנסה הגדרות מהירות יותר מול ה-eval שלך. בתוספת: שורת "Earlier in this session" ב-/tasks שמחזירה סאב-אייג'נטים שסיימו.

תיקונים בולטים

שרתי MCP בלחיצת-יד ישנה (handshake קודם) לא התחברו או החזירו תוצאות ריקות כי CC הכריז על הרחבה שהוא משתמש בה רק עם שרתים חדשים - תוקן. קריאת MCP ארוכה על קונקטור של claude.ai שלפעמים לא דיווחה תוצאה אחרי --resume - תוקן. /diff נשבר על ריפו עם קובץ בשם HEAD, ו-/context שלח את כל הגריד החזותי לקלוד בכל תור (עכשיו רק הטבלה). ותיקון חמור-פוטנציאל ל-CI: claude -p ב-auto mode יצא 0 גם כשפעולות נדחו בגלל היעדר בדיקת-בטיחות זמינה - כעת יוצא 1.

מעקב מאתמול: מוד ה-privacy (דחיית User-Agent עם מייל) עדיין לא מופיע ב-release notes של גרסה מתויגת - גם לא ב-2.1.319. בקשת-האישור הרשמית מ-2.1.317 היא עדיין השכבה המתועדת היחידה במהדורות.

חיבור אפשרי לפרויקטים שלך: אם יש לך שרתי MCP איטיים (חיפוש, שליפות) בסביבת מענה - 2.1.319 הופך אותם לרקעיים; ואם אתה מריץ claude -p ב-CI של dorgames, הפעל denyInsteadOfPrompting ובדוק את תיקון קוד-היציאה - שניהם מונעים "ירוק כוזב".

046.11: libghostty 1.0 - אמולטור הטרמינל של Ghostty כספריית C ניידת עם ABI יציב; כבר בתוך JetBrains ומיליוני משתמשים+

מה זה ולמה כאן

מיטשל השימוטו הודיע (6.11): libghostty-vt 1.0 - ליבת אמולציית-הטרמינל של Ghostty כספריית C ניידת ומהירה, עם ABI יציב ואכוף. שנה אחרי שהוסבר "למה בכלל", התשובה מגיעה בצרכנים: הטרמינל ב-IDEs של JetBrains (IntelliJ, PyCharm, GoLand) רץ כבר על libghostty - 12.5 מיליון משתמשים פעילים לפי דיווח JetBrains; ל-Neovim יש PR מאושר שמחליף את libvterm (וסוגר issue בן 10 שנים על reflow של scrollback בשינוי-גודל); ובסך הכל הספרייה רצה בפרודקשן אצל מיליונים, במאות מוצרים חופשיים ומסחריים.

למה זה משנה

אמולציית-טרמינל היא אחת מפיסות התשתית הכי קשות לכתוב נכון (וישראל), ועד היום כל כלי-מפתחים כתב או הכניס נכון-חלקית משלו. ABI יציב 1.0 הופך את זה לתלות שאפשר לבנות עליה - באותה משמעות שבה Tree-sitter איחדה פרסינג של תחביר. אם אתה בונה כלי מפתחים, IDE, טרמינל-בדפדפן או TUI - כבר לא צריך לכתוב אמולטור.

חיבור אפשרי לפרויקטים שלך: אם dorgames או כלי-פנים שלך יצטרך אי-פעם טרמינל מוטמע (מסוף-בילדים, ריפל חי בתוך דשבורד) - זו הספרייה, עם חותמת-איכות של JetBrains. וגם כשיעור: "למכור" פרויקט-תשתית דרך הפרסרים הגדולים קודם (JetBrains, Neovim) הוא מה שהפך 1.0 לאירוע.
