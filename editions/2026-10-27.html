01Claude Code 2.1.311: ההתנגשות ב-200K הופכת ל-compaction, ותיקוני subagents ו-MCP+

מה פורסם

v2.1.311 ב-26.10 ב-21:51 UTC. גרסת יציבות גדולה: עשרות תיקונים, בעיקר סביב סשנים ארוכים, subagents, MCP וסשנים מרוחקים.

התיקון הבולט

סשנים בקונטקסט רגיל שהתנגשו ב-200K טוקנים נעצרו עם "Usage credits required for 1M context" - בטעות. מעכשיו Claude Code מבצע compaction לשיחה וממשיך. מי שהריץ סוכנים ליליים על קבצים גדולים וקם לסשן מת - זו הסיבה.

subagents ו-MCP

subagents לא יכלו להשתמש בכלים משרתי MCP שסיימו להתחבר אחרי שה-subagent התחיל; פסיקה (interrupt) לא נכנסה לתוקף עד timeout כששרת MCP לא ענה על קריאת resource או skill היה בהורדה; claude mcp add/remove ו-/mcp רשמו את התיקייה הנוכחית במקום את רשומת הפרויקט כשהופעלו מתחת לשורש הריפו. ובנושא זיכרון: אחרי compaction אוטומטי Claude ראה תוכן ישן של MEMORY.md ו-CLAUDE.md אם הם נערכו קודם בסשן.

עוד שווה לדעת

התארים ארוכים בהתחלה ואחרי קריאת/עריכת קבצים כשב-CLAUDE.md יש פריט רשימה ארוך מאוד - תוקן. claude -p ו-SDK שמרו הודעות transcript בסדר שגוי. hooks של SubagentStop רצו פעמיים בדקה במקום פעם אחת בסיום. ל-self-hosted runners נוספו --hold-idle-file ו---max-hold-min. פקודות shell שמגיעות ל-timeout מציגות כעת את הפלט שנצבר וממשיכות ברקע.

חיבור אפשרי לפרויקטים שלך: אם מענה או dorgames מריצים Claude Code ב-CI או ברקע, זה עדכון לביצוע מיידי - תיקון ה-200K וה-subagents פוגע בדיוק בתהליכים אוטומטיים ארוכים. ואם אתם כותבים CLAUDE.md ארוכים: פריט רשימה אחד ענק גרם לקיפאונים - עדיף לשבור לשורות. זו הצעה, לא דיווח על תצורה קיימת. הסתייגות: קראנו את רשימת הגרסה ולא הרצנו אותה.

02GPT-6.1 Terra: דולר למיליון טוקני קלט, 1.05M קונטקסט - וזמינות באותו יום ב-Bedrock וב-Copilot+

מה פורסם

ב-26.10 שיחררה OpenAI את GPT-6.1 Terra (gpt-6.1-terra): מודל "מהיר ויעיל" לראייה חזותית, computer use מדויק וכתיבה - בחצי מחיר מ-GPT-6.1 Sol: דולר למיליון טוקני קלט (5 סנט קלט שמור ב-cache) ו-5 דולר למיליון פלט. חלון קונטקסט 1,050,000 טוקנים (עד 922K קלט, עד 128K פלט), knowledge cutoff יוני 2026, רמות reasoning.effort מ-none עד max. קלט: טקסט ותמונה; פלט: טקסט. tool calling דורש Responses API. לפי ההערכה של OpenAI, Terra מסיים משימות פי 3+ מהר מ-GPT-6 Astra (הסתייגות: הערכת הספק).

המלכודת במחיר הארוך

פרומפטים מעל 272K טוקני קלט מסוכמים ב-כפל 2 על קלט ו-cache ו-1.5 על פלט - על כל הבקשה. כלומר היתרון של הקונטקסט הענק מתייקר בקפיצה, לא בהדרגה. Batch ו-Flex ב-50% הנחה; fast mode בכפל 2.

זמינות

באותו יום: GA ב-Amazon Bedrock, והגעה ל-GitHub Copilot במחירון הספק, מופעל אוטומטית תחת מדיניות המודל ברירת-המחדל. הטריפטיך הזה (API + Bedrock + Copilot באותו יום) הוא הדפוס החדש של שחרורי OpenAI.

חיבור אפשרי לפרויקטים שלך: אם מענה או Podcasto מעבדים מסמכים ארוכים או אפיזודות שלמות דרך OpenAI, Terra ב-$1/M עם 1.05M קונטקסט משנה את חשבון העלות - אבל בדקו קודם אם הבקשות חוצות 272K, שם התמחור קופץ. ומי שמשתמש ב-Copilot בארגון: המודל נדלק אוטומטית תחת מדיניות ברירת-המחדל - שווה לבדוק שהיא מכוונת כמו שרוצים. זו הצעה, לא דיווח על שימוש קיים.

03Cloudflare חושפת: מאגר KV קטן מחלון הקונטקסט + באג SGLang = דליפת תוכן בין לקוחות ב-GLM-5.3+

מה פורסם

ב-26.10 פרסמה Cloudflare חשיפה מתואמת (עם SGLang) על תקרית בידוד בין-דיירים במודל GLM-5.3 ב-Workers AI: בין 27.8 ל-9.9, 155 תגובות לפרומפטים מעל 681,280 טוקנים החזירו תוכן מבקשות של לקוחות אחרים. אין ראיות לניצול זדוני; המודל הורד ושוחזר באותו יום.

שני כשלים שהצטלבו

קונפיגורציה: GLM-5.3 הופעל עם חלון קונטקסט 1,048,576 טוקנים, אבל מאגר ה-KV cache ב-GPU ה-prefill הכיל רק 681,280. Cloudflare ידעה על הפער והניחה שהמנוע יחזיר שגיאה - בדיקות קדם-השקה החזירו HTTP 200, אז לא בדקו את התוכן. באג במנוע: במצב disaggregated (prefill ו-decode בצמתים נפרדים), בקשה דחויה סומנה כ"חיה": הפרומפט הוחלף בטוקן placeholder אחד, ה-decode קיבל "ההעברה הושלמה" אחרי דף KV אחד בלבד, והמשיך לייצר תוך קריאת 7 דפי cache שמורים - שעדיין החזיקו בקשות של משתמשים קודמים. דפי ה-KV לא מאופסים בין בקשות; הבעיה דווחה ל-SGLang כבר ב-6.7 ותוקנה ב-v0.5.20-v0.5.22.

הלקחים לכל מפעיל מודלים

שלושה דברים ש-Cloudflare מפרטת ושווים העתקה: לבדוק גודל מאגר KV מול אורך הקונטקסט מהמנוע החי לפני כל פריסה (המאגר נגזר מזיכרון GPU פנוי, לא מקונפיגורציה - כל שינוי קוונטיזציה או TP משנה אותו); לא לקבל HTTP 200 כהוכחה שהתוכן תקין; ומפעילי SGLang: לשדרג ל-v0.5.22 ומעלה.

חיבור אפשרי לפרויקטים שלך: אם מענה או Podcasto צורכים מודלים דרך Workers AI או מפעילים SGLang/vLLM עצמאית לקונטקסטים ארוכים - הבדיקה היא בדיוק נקודת התורפה הזו: תגובת 200 עם תוכן מלקוח אחר. זו שאלת בדיקה, לא דיווח על שימוש קיים.

04Gemini API: בקשות נשמרות כברירת מחדל בפרויקטים חדשים בתשלום+

מה פורסם

ב-26.10, ב-changelog של Gemini API: פרויקטים חדשים בתכנית בתשלום שמשתמשים ב-Generate Content API (generateContent, streamGenerateContent, batchGenerateContent) ישמרו בקשות כברירת מחדל (store=true), בהתאמה ל-Interactions API.

למי זה לא חל ואיך מכבים

פרויקטים קיימים נשארים בהגדרה הנוכחית - השינוי חל רק על פרויקטים שנוצרים מעכשיו. ביטול: store=false על בקשות בודדות, או כיבוי הלוגינג של Generate Content API בלוח Logs and Datasets.

למה זה משנה

שינוי ברירת-מחדל שקט שקובע אם הפרומפטים והתגובות שלך (וכל מה שמוזרק לתוכם - קוד, מסמכים, נתוני משתמשים) נשמרים אצל הספק. בסביבות פיתוח מחוברות לדאטה אמיתי, ההבדל בין "פרויקט ישן" ל"פרויקט חדש שנפתח לבדיקה מהירה" הוא בדיוק המקום שבו מתפספס.

חיבור אפשרי לפרויקטים שלך: אם מענה, Podcasto או dorgames עובדים עם Gemini API בתשלום ופותחים פרויקט חדש (staging, POC, סביבת בדיקות) - ההגדרה החדשה דורשת החלטה מודעת: להשאיר את הלוגינג דולק (שימושי לדיבוג) או לכבות אותו במפורש. זו שאלת בדיקה, לא דיווח על שימוש קיים.
