01Sonnet 5.5: קפיצה ביכולת, לא הוזלה במחיר לטוקן+

מה יצא

Anthropic השיקה את Claude Sonnet 5.5, זמין גם ב-Claude Code וגם ב-API תחת claude-sonnet-5-5. הוא ברירת המחדל של משפחת Sonnet ב-Claude Code 2.1.284. מחיר ה-API נשאר $2 למיליון טוקני קלט, $10 לפלט ו-$0.20 לקריאת cache. טענת החיסכון של עד 30% היא על עלות המשימה: לפי Anthropic, המודל משתמש בפחות טוקנים ומייצר פלט מהר ביותר מ-30% לעומת Sonnet 5. חלון ההקשר הוא מיליון טוקנים.

המספרים ומה לא להסיק מהם

ב-Terminal-Bench 4.0 Anthropic מדווחת על 70.6% מול 10.3% ל-Sonnet 5; ב-FrontierCode, 46.2% ב-Max או 52.1% ב-Xhigh. אלה מבחני ספק בתצורות מאמץ שונות, לא הבטחה שהשדרוג ישפר כל workload. אפילו Anthropic מציינת שבמבחן FrontierCode מאמץ Max נתן ציון נמוך מ-Xhigh בגלל עריכות מחוץ להיקף. במקביל GitHub הכריזה על זמינות ב-Copilot למנויים מתאימים, בפריסה הדרגתית.

למה זה שלך: במענה, Sonnet 5 הפסיד ל-gpt-5.6-luna בבייק-אוף העברי שלך, עם פער מחיר וזמן גדול. Sonnet 5.5 משנה את ההיפותזה, לא את תוצאת הבדיקה ההיא: כדאי להשוות אותו על אותן שאלות, אותם מסמכים ומדדי recall/אימות, ולמדוד עלות לשאילתה שעברה את השופט, לא מחיר לטוקן. ב-podcasto הוא מועמד למשימת כתיבה מוגדרת היטב, אך לא סיבה להחליף מודל בייצור בלי eval עברי.

02Claude Code בונה eval ואז משפר מול סט מוחזק בצד+

מה יצא

ב-skill הרשמי claude-api נוספו תהליכי /claude-api build-eval ו-/claude-api hillclimb. הראשון מראיין את המפתח, בונה דוגמאות מתוך תעבורת ייצור (אחרי בדיקת שמירת נתונים ורגישות), באגים, מקרים ידניים וקוד; מציג את הדוגמאות לאישור; בוחר בודק קוד כשאפשר או שופט LLM כשצריך; מריץ baseline עם חזרות ורווח סמך. הוא בודק גם אם אותו פלט מקבל ציון לא עקבי, אם תקלות API מתחפשות לשונות מודל, ואם המדד כבר רווי סביב 95%.

החלק המעניין

hillclimb משנה פרמטר אחד בכל סבב: פרומפט, כלי, skill, מודל/effort או harness. הוא מפריד train מ-test, מראה לו רק כישלונות train, ולא מעתיק את התשובות לתוך הפרומפט. אם השיפור קטן מהרעש הסטטיסטי, הוא לא אמור להיחשב הישג. בדוגמה פנימית של Anthropic ל-44 פניות תמיכה, חיפוש האופטימיזציה התבסס על 30 וההכרעה על 14 מוחזקות בצד; המדגמים קטנים והמספרים הם הדגמה, לא התחייבות לאפליקציה אחרת.

למה זה שלך: זה בדיוק הגבול שנדרש בשדרוגי הכתב והשופט של podcasto: לא לכוונן שוב ושוב לפי שלושת הפודקאסטים המוכרים בלבד. להחזיק פרקי מבחן שלא נחשפים ל-hillclimb, ולפרק ציונים לפי אורך, נאמנות למקור ומרקם דיאלוג. בבייק-אוף של מענה יש לך כבר שאלות עבריות אמיתיות; אפשר להשתמש באותו עיקרון כדי להבחין בין שיפור retrieval לבין שופט שהפך סלחני.

03Codex 0.158: OAuth ל-MCP עם client secret, ואבטחת חיבורי WebSocket+

מה השתנה

בגרסה היציבה 0.158 של Codex CLI, OpenAI הוסיפה חיבור לשרתי MCP שדורשים OAuth client secret רשום מראש, כולל codex mcp add --oauth-client-secret. בנוסף exec-server ו-app-server יכולים לאבטח חיבור WebSocket ישיר באמצעות bearer token. אישור על קלט מסוף לפקודות עם הרשאות גבוהות מופעל כברירת מחדל; תיקונים נוספים מכסים sandbox ב-Windows וב-Linux, Git metadata בשורשים בני-כתיבה ותצוגת Mermaid.

הסייג

זו תמיכה טכנית בסוג חיבור, לא הוכחה שכל שרת MCP דורש secret או שהאימות שלו מוגדר נכון. גם bearer token לחיבור ישיר הוא יכולת, לא הבטחה שהוא הופעל במערכת קיימת.

למה זה שלך: ל-podcasto כבר יש endpoint של MCP. לפני שמחליפים client או מניחים ש-OAuth עדיף על מפתח ה-pk_ הקיים, צריך לבדוק את חוזה האימות בצד השרת ואת ה-discovery בפועל. השינוי הזה שימושי במיוחד אם בעתיד תפריד לקוחות אוטומטיים לפי הרשאות, במקום להעביר אותו מפתח רחב לכולם.

04Cloudflare cf: CLI מוכוון סוכנים לכל משטח ה-API+

מה יצא

Cloudflare פתחה בטא של CLI בשם cf, שמרחיב את כיסוי הפקודות מכ-280 פעולות ב-Wrangler ליותר מ-3,000 פעולות API. JSON הוא פלט ברירת המחדל, cf cli search מחפש פקודה מתיאור בשפה טבעית, ו-cloudflare.config.ts הופך הגדרות לפרויקט TypeScript עם השלמה ואימות טיפוסים. Vite הוא מסלול הפיתוח החדש; cf migrate ממיר פרויקטים, אך פרויקטי JavaScript שתלויים ב-esbuild ימשיכו להעביר חלק מתהליכי הפיתוח והפריסה דרך Wrangler. Cloudflare אומרת ש-48% משימוש Wrangler בשבוע הקודם הגיע מסוכנים, נתון פנימי שלה.

מה ללמוד מזה

הבחירה ב-JSON, חיפוש פקודות וטיפוסים משרתת סוכן שצריך לגלות יכולת בלי לדחוף אלפי תיאורים לפרומפט. אבל CLI שמסוגל גם לפרוס, לשנות אבטחה ולרכוש דומיין דורש הרשאות מדורגות ואישור לפעולות בעלות השפעה. זו בטא; אין כאן המלצה לבצע מיגרציה אוטומטית.

למה זה שלך: השבוע נתיב כתיבת הרדאר לסופהבייס נשבר כי הוא נשען על POST מתוך דפדפן, בעוד git push ל-GitHub Pages נותר מסלול מפורש וניתן לבדיקה. cf מדגים את העיקרון הארכיטקטוני שמאחורי זה: פעולה חוזרת של סוכן צריכה כלי ממוסד עם פלט מכונה, לא טריק DOM. למענה ול-dorgames, אם נשקלת תשתית Cloudflare, בדוק הרשאות וחיוב לפני חיבור של סוכן ל-CLI הרחב.

05EmDash 1.0: CMS פתוח עם MCP ותוספים מבודדים+

מה יצא

Cloudflare הכריזה על גרסה יציבה של EmDash, CMS פתוח הבנוי על Astro. עורכים עובדים בממשק ניהול; סוכנים יכולים לעבוד דרך API, CLI או שרת MCP מובנה. הגרסה מוסיפה registry מבוזר לתוספים על בסיס AT Protocol: המפרסם שומר על הזהות ורישום הגרסאות, והקטלוג יכול לסנן תצוגה בלי לשנות את קוד המהדורה. לפי Cloudflare, הבלוג שלה עבר למוצר באוגוסט.

גבול האמון

תוסף מבודד מקבל אחסון משלו בלבד. קריאה של תוכן, גישה למדיה, כתיבה, דוא"ל או יציאה לרשת ניתנות כיכולות נפרדות ומוצהרות; בדף התקנה אפשר לראות מה הוא מבקש. ב-Cloudflare התוספים רצים ב-Dynamic Workers, וב-Node.js בתהליך workerd נפרד. זה תכנון הרשאות, לא הוכחת אבטחה מוחלטת, ומעבר CMS הוא פרויקט בפני עצמו.

למה זה שלך: ב-podcasto ובמענה יש תוכן משתמש וסודות תפעוליים. הדוגמה מעניינת פחות כתחליף לאתר קיים ויותר כמודל הרשאות לתוספי צד שלישי: לכל סוכן או כלי לתת רק את היכולת, הנתונים והיעדים הדרושים לו. ה-MCP המובנה מדגים עריכת תוכן דרך ממשק רשמי, אך אינו סיבה לחשוף את ספריית הפרקים או מסמכי לקוחות ל-plugin לא בדוק.
