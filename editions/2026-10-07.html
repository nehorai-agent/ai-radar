01Claude Code 2.1.292: הרשאות שאינן נעלמות, ומשימות שאינן נופלות בין סשנים+

מה השתנה

הגרסה פורסמה ב-6.10 ב-18:59 UTC. מתוך רשימה ארוכה של תיקונים, אלה נוגעים ישירות לעבודה עם סוכני קוד: קריאות כלים בזמן שה-worker של hooks מתחיל מחדש כבר אינן נענות בלי ה-permission hooks של plugins; hook שקרא next(e) ואז נכשל בזמן interruption כבר לא מעביר את הפעולה; ו-hook שמאשר כלי שדורש תשובה שלך אינו מדלג על חלון השאלה או אישור התוכנית.

גבולות קבצים: תיקון לקריאת עותקי קבצי ultrareview מתוך sandbox, החלפת symlink בזמן קריאת PDF או notebook, וקריאת נתיבי רשת UNC שעברה בלי שאלת הרשאה דרך PreToolUse או auto mode. עוד תיקון: שינוי או הופעה של read-deny path באמצע סשן מפסיקים grants והזרקת credentials מתוך הקבצים המכוסים. הרשימה אינה אומרת שהתרחשה דליפה אצל משתמשים.

משימות והמשכיות: הרצת claude -p ו-Agent SDK כבר אינה עוצרת פקודת רקע חמש שניות אחרי התוצאה האחרונה; claude -p ממתין גם ל-wakeup מתוזמן. תוקנו משימות שמורות שנוצרו אחרי resume, branch או clear ולא פעלו, וכן loop שנעלם אחרי restart של התהליך. אלה תיקונים חדשים, לא חזרה על תיקון ה-compaction של אתמול.

כלים למפתחי plugins: פרמטר effort לקריאת Agent, prompt caching עבור $.model.complete ב-mods, ו---marketplace ב-plugin install. חשוב גם: בדיקת expect כושלת בתוך hook שנרשם בבדיקת plugin מכשילה כעת את הבדיקה, במקום לעבור בשקט. Code Review קורא את כללי CLAUDE.md מענף הבסיס כשאותו קובץ משתנה ב-PR.

מה לקחת מזה

"הסוכן לא התלונן" אינו הוכחה שהבדיקה עברה או שהתזכורת נשמרה. עכשיו Grep ו-Glob לא מדווחים סתם "אין תוצאות" על נתיב שאי אפשר לקרוא: הם מנסים שוב פעם אחת או מודיעים. וגם קבצי טקסט מעל 256KB שסומנו ב-@ אינם נשמטים בלי הודעה.

החיבור אליך: בעבודה על podcasto ומענה, שמור בדיקת רגרסיה קטנה לצד כל משימה מתוזמנת: ליצור אותה, לעשות resume, לוודא שהיא פועלת פעם אחת. אם יש לך plugins, בדוק דווקא restart של worker ו-hook שנכשל, לא רק מסלול מוצלח. לסקירת PR שמשנה CLAUDE.md יש עכשיו יתרון נוסף: ההוראות שהקוד החדש מנסה להכניס אינן מכתיבות את הביקורת של עצמו.

הסתייגות

קראתי את כל ה-release notes, לא הרצתי את הגרסה ולא שחזרתי את הבאגים. אין ברשימה מיפוי מלא של הגרסאות שהושפעו מכל תקלה. היא אינה מוכיחה ש-plugin מסוים שלך בטוח.

02WinDbg MCP: לחקור crash עם ראיות, לא עם ניחוש משכנע+

מה הושק

Microsoft הכריזה ב-6.10, 18:14 UTC, על MCP מובנה ב-WinDbg החל מגרסה 1.2610.1001.0. הסוכן יכול לבדוק crash dump, target חי או Time Travel Debugging trace, להריץ פקודות debugger, לעיין בקוד ולהציע סקריפט חקירה. התמיכה הרשמית היא VS Code עם GitHub Copilot ו-Copilot CLI. Codex ולקוחות אחרים הם best-effort, לא נתיב נתמך רשמית.

הפרט החשוב: מקומי אינו פרטי בהכרח

ה-client מדבר ב-stdio עם proxy, וה-proxy מתחבר ל-WinDbg דרך named pipe מקומי נפרד לכל process. יש רק client פעיל אחד לכל סשן. אבל ה-client עדיין יכול לשלוח הקשר מה-debugger לשירות המודל שלו, ולוגים יכולים להכיל פקודות ונתוני target. לכן crash dump עם מידע רגיש אינו נהפך לבטוח רק כי החיבור ל-debugger מקומי.

שתי הגנות נפרדות

Secure Mode מופעל כברירת מחדל ומגביל הרצת קוד לא מהימן, יצירת תהליכים ופעולות קבצים מסוכנות. להפעלה מלאה צריך להתחיל את MCP לפני חיבור ל-target; אחרי חיבור נכנסים למצב חלקי עם אזהרה. לאחר הפעלה הוא נשאר עד restart של WinDbg. הוא לא בודק ולא הופך extension לאמין.

הגנת prompt injection מסווגת פלט debugger בפעולות מוגנות דרך שירות המודל של ה-client. היא דורשת MCP sampling ועשויה לצרוך עוד טוקנים. כשהסיווג לא יכול לרוץ, הפעולה המוגנת נכשלת בלי להחזיר פלט. זה הסבר שימושי ל"MCP מחובר, אבל הכלי לא עונה". כיבוי ההגנה אינו מכבה Secure Mode, ולהפך.

החיבור אליך: אין לי ראיה שאתה מפעיל WinDbg או שהפרויקטים שלך דורשים debugger של Windows. כן שווה לקחת את תבנית החקירה ל-dorgames ולשאר הסוכנים: "תן סיבה משוערת, פלט שתומך בה, והנחות שעדיין לא נבדקו". אם יש crash מקומי ב-Windows, אפשר לנסות על dump סינתטי ולא רגיש; לא על dump של משתמש. ולשרת MCP שלך כדאי להחזיר סיבת כשל ברורה כשיכולת client חסרה, במקום להיראות תקוע.

הסתייגות

זו הכרזת Microsoft ותיעוד שלה, לא מדידת דיוק עצמאית. לא בדקתי אם הסוכן באמת מוצא את סיבת הקריסה או כמה עולה שכבת הסיווג. כל מסקנה עדיין דורשת אימות מול מצב ה-target והפקודות שהורצו.

03Bubble MCP בבטא: Claude Code ו-Codex בונים בתוך עורך no-code+

מה יצא

Bubble הכריזה ב-6.10 ב-15:15 UTC על Agent 2 לכל האפליקציות ועל MCP בבטא לסוכנים חיצוניים. אלה שני מוצרים שונים: Agent 2 הוא הסוכן בתוך Bubble; MCP מאפשר ל-Claude Code או Codex ליצור ולערוך אפליקציית Bubble, עם המודל והחשבון שאתה בוחר.

בתיעוד יש כלים אמיתיים לעמודים, workflows, data types ו-privacy rules, API Connector, רשומות וקבצים. התוצאה נשארת אפליקציית Bubble שאפשר לערוך ויזואלית, לא קוד עצמאי שיצא מהריפו. קיימים גם check_app_issues, בדיקות, preview links, undo ו-savepoints. החיבור דורש OAuth; הוא משתמש ב-CIMD, ולכן לא כל client נתמך עדיין. Bubble מציינת ש-Cursor ו-Composio אינם תומכים בסטנדרט הזה כרגע.

מה הוא לא עושה

בגרסת ההשקה MCP אינו קורא logs, אינו מבצע merge של branches ואינו עושה deploy. בתיעוד יכולת "Debug" פירושה חקירה ועריכה של האפליקציה, לא גישה ללוגים. לכן אל תסיק מ"יכול כמעט הכול" שיש פה סוכן production מקצה לקצה.

עלות ובדיקות

MCP לא צורך את AI credits של Bubble, אבל צורך שימוש אצל ספק המודל שלך. הסוכן המובנה כן צורך credits, והם שייכים לאפליקציה ומשותפים לכל עובדיה. ב-20.10 מחיר Starter Web עולה ל-$39 בחיוב חודשי או $32 לחודש בחיוב שנתי, לפי ההכרזה. "פי 1.5 יותר מדויק ופי 2 יותר פונקציונלי" הן טענות Bubble על Agent 2, לא תוצאות עצמאיות ולא מדידה של MCP.

החיבור אליך: אין כאן סיבה להעביר את מענה או podcasto ל-Bubble. יש כאן דוגמה למבנה טוב של כלי עריכה לסוכן: לקרוא מבנה, לבצע שינוי קטן, לבדוק issues, להראות preview, ולשמור נקודת חזרה. אם תבנה יכולות MCP לעריכת תוכן או מסכים אצלך, ההפרדה בין שינוי לבין deploy יכולה להיות חשובה יותר משם המודל. ניסוי ב-Bubble הגיוני רק אם תרצה prototype נפרד שלא תלוי בריפו הקיים.

הסתייגות

לא התחברתי לחשבון Bubble ולא בניתי אפליקציה. undo ו-savepoints אינם הוכחה שכל שינוי או כל מחיקת נתונים ניתנים לשחזור. גם "אין AI credits" אינו אומר שאין עלות מודל או עלות hosting.
