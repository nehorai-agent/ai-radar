01Claude Code 2.1.299: תיקוני גבולות, לא בידוד של הכול+

מה פורסם

הגרסה פורסמה היום ב-05:49:42 בישראל. מתוך changelog ארוך, האות החשוב הוא החיבור בין sandbox, הרשאות MCP ומודים. אלו תיקוני יצרן, לא סקירת אבטחה עצמאית.

כשהגבול שונה מהכוונה

פקודת shell בתוך sandbox יכלה לכתוב לתיקיית --plugin-dir, שהקוד בה נטען ומורץ מחוץ ל-sandbox. הגבלת פקודה אינה מספיקה אם הפלט שלה הופך לקוד בשכבה אחרת. תוקנו גם גישה דרך symlinks ב-macOS ובדיקה חוזרת של תיקיות allow שהוחלפו בקישור.

כלל MCP בשם mcp__a התיר גם שרת בשם a__b או a_. כעת allow מגיע רק לשרת ששמו נכתב. המחברים מנחים להשתמש ב-mcp__<server>__* עם השם המנורמל המלא. תוקנו גם deny/ask בשמות עם double underscore והתחברות לפני בדיקות policy בחלק ממסלולי headless ו-SDK.

plan mode יכל להריץ כתיבה אם hook אישר אותה. מודים יכלו להשאיר ריצה headless פעילה מעבר ל---max-turns, --max-budget-usd או interrupt באמצעות prompt בסוף כל turn. הרשימה מציינת תיקונים לשניהם. זו גם בעיית עצירה ועלות.

מה ה-sandbox עדיין אינו

לפי התיעוד הנוכחי, הוא עוטף shell והילדים שלו. כלי קבצים, MCP servers ו-hooks פועלים מחוץ לו תחת מנגנונים אחרים. ברירת המחדל לקריאות shell כוללת רוב המכונה, גם קבצי credentials, אלא אם הוגבלה. התיקונים אינם מבודדים את כל התהליך.

גם חיסכון בהקשר

idle compaction בטרמינל מכווץ שיחה של לפחות 200K טוקנים אחרי כ-54 דקות ללא פעילות, לפני פקיעת prompt cache של שעה. אפשר לשנות סף או לכבות. ההגדרות דורשות 2.1.290 ומעלה לפי ה-release, ולכן אין להסיק שכל המנגנון נולד היום. זה מצמצם עיבוד מחדש, לא מבטיח ששום פרט לא יאבד.

חיבור אפשרי לפיתוח מענה, Podcasto ו-dorgames: אם עובדים עם מודים או MCP, בדיקות סביבת הפיתוח צריכות לכלול שם שרת דומה, symlink וגבול תקציב. זו רשימת בדיקות ל-workflow, לא קביעה שההתקנות שלך חשופות. לא שיניתי גרסה או config.

02Pensieve 0.7.0: לא לחשב שוב את אותו קטע קוד+

החדש הבוקר

0.7.0 פורסמה ב-06:09:18 בישראל: שימוש חוזר בווקטורים בזמן indexing, תוצאות לקבצים של ה-worktree שבו הסוכן פועל, search מה-shell והורדת משקלי הטקסט בלבד של EmbeddingGemma 2, 550MB במקום 1.5GB. בחירת המודל וברירת המחדל לאינדקסים חדשים הגיעו ב-0.6.9 ב-04:46:22. אינדקס קיים שומר את המודל שלו.

המנגנון המדויק

בקוד של תג 0.7.0, שימוש חוזר בקוד נעשה כשגם הנתיב היחסי וגם טקסט הקטע זהים לקטע שכבר חושב בריפו. מעתיקים וקטור במקום לחשב embedding שוב על קוד שלא השתנה ב-worktree או בקובץ ערוך. זה אינו cache לכל טקסט זהה בכל מקום: הנתיב משתתף בייצוג. החיסכון הוא בזמן indexing, לא הוכחה שכל חיפוש מהיר פי שניים.

חיפוש מקומי אינו בהכרח הקשר מקומי

המוצר מחבר SQLite, אינדקס exact-text ו-turbovec לחיפוש במסמכים, קוד ושיחות סוכנים. embedding רץ מקומית. כתיבת summaries אופציונלית ויכולה לעבור דרך Claude Code או Codex, כך ש-local-first אינו הבטחה שכל תוכן נשאר במחשב. ה-app הוא ל-macOS, וה-backend וה-map תומכים גם Linux.

scope אוטומטי ב-stdio נבחר לפי תיקיית העבודה. מחוץ לריפו הוא אומר הכול; חיבור HTTP ללא scope מפורש אומר הכול. scope מסנן אינדקס משותף, לא יוצר מאגר נפרד לכל פרויקט. המקור מפרט החרגת קבצים דמויי סודות לפי שמות, לא זיהוי סמנטי של כל סוד בתוכן.

הטענה על מהירות מול המדידה

המחבר מדד 42.7 מול 22.3 chunks לשנייה ב-M4 Max על אותם 1,200 קטעים. באחוז הפגיעות הראשון על 1,625 שאילתות בשלושה ריפואים: 68.0% מול 68.1% לשיטה עם כללי חיפוש, אבל הביצועים שונים לפי סוג שאלה. זה benchmark של המפתח, לא רפליקציה או בדיקת עברית. מדידת Claude Code ב-README נעשתה עם 0.5.6 על איתור קובץ בלבד, ואינה תוצאת 0.7.0.

חיבור אפשרי לפיתוח מענה ו-dorgames: אם משתמשים ב-worktrees, כדאי לבדוק שחיפוש מחזיר את הקובץ בענף הפעיל ולא עותק של main. ל-Podcasto, אם מאנדקסים תמלילים, צריך להפריד בחירת מקורות, scope ומודל summaries. זה כלי לפיתוח וחיפוש מקומי, לא תחליף אוטומטי ל-Qdrant של שירות.

03Kilo MCP: שני כלים, הרבה סמכות+

מה הוכרז

Kilo פרסמה ב-13.10 ב-17:54:47 בישראל שרת MCP מרוחק לפלטפורמה שלה. לקוח תומך MCP יכול לשאול על שימוש ועלות, לנהל agent profiles ולהתחיל או לנהל cloud agents. החיבור משתמש ב-OAuth ופועל בזהות המשתמש, לא בארגון קבוע אחד.

למה רק search ו-call

במקום לשלוח תיאור כלי לכל endpoint, search מחפש בקטלוג API ומחזיר endpoints והקלט הנדרש. call מפעיל endpoint שנבחר. זו טעינה לפי צורך של ממשק גדול. Kilo מציינת שפעולה פשוטה דורשת בדרך כלל חיפוש וקריאה אחת, והקמת סוכן יכולה לדרוש כמה חיפושים. אין בפרסום benchmark של חיסכון בטוקנים.

המחיר של דחיסה

אותו call יכול להגיע למידע, לעדכון פרופיל, למחיקה או להפעלת סוכן בענן. התיעוד של הלקוח מגדיר allow/ask/deny לפי שם כלי MCP ומאפשר Approve Always. מסקנת התכנון: אישור גורף ל-call גנרי אינו מבדיל כשלעצמו בין endpoint קורא ל-endpoint כותב. הפרסום אינו מפרט מספיק כדי לאמת מגבלות OAuth ברמת כל פעולה; אין להסיק שהכול read-only או שכולו מאושר.

אם המשתמש חבר בכמה ארגונים, Kilo מבקשת לציין לאיזה מהם מתכוונים. זו בחירת יעד לפעולה, לא פרט קוסמטי. יצירת cloud agent יכולה גם להוסיף צריכת שירות; לא נבדקו כאן מחירים, תקציב או גבולות חיוב.

חיבור אפשרי למענה ולתהליכי Podcasto: אם בונים MCP לממשק גדול, אפשר ללמוד מהקטלוג הדינמי, אבל להפריד בצד השרת קריאה, כתיבה והוצאה כספית. endpoint, חשבון, ארגון ופרמטרים צריכים להיכלל בהחלטת האישור. אין כאן המלצה לחבר חשבון או להחליף תשתית.

הכרזת Kilo · הרשאות CLI · OAuth ואישור כלי

הלקח לבוקר: cache חוסך חישוב, catalog חוסך הקשר, sandbox מגביל חלק מהפעולות. כל אחד פותר בעיה אחרת. לא להחליף מדידת דיוק בביצועי indexing, ולא להחליף הרשאה ל-endpoint בהרשאה לשם כלי.

סוננו: Muse Wonder הוכרזה ב-12.10, magents ו-Ruflo תוארו מחדש אחרי releases קודמים, ו-Codex הציג תגי alpha ללא אות יציב חדש. לא הוספו כדי למלא מכסה.
