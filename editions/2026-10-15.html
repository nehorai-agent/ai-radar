01Claude Code 2.1.300: תמליל שנוח לשחזר, רגיש יותר לשיתוף+

החדש אחרי מהדורת אתמול

2.1.300 פורסמה ב-14.10 ב-21:24:25 בישראל. זו אינה שוב רשימת האבטחה של 2.1.299. הגרסה משנה את מה שנשמר בתמלילים מקומיים ומתקנת מצבים שבהם חידוש סשן איבד או חזר על עבודה.

התמליל הוא יותר מהצ'אט

התמליל המקומי מתעד כעת גם את system prompt, הכלים והפרמטרים של כל בקשת API, כדי לאפשר שחזור מדויק של הבקשה. פירוש מעשי: קובץ שמשתפים לצורך debug יכול לכלול הקשר עשיר יותר מההודעות שרואים על המסך. ה-release אינו מציג זאת כהצפנה או מבטיח סינון של כל פרט רגיש. אין להסיק שהגרסה שולחת את הקובץ אוטומטית החוצה.

במקביל תוקן רישום OpenTelemetry של prompt שמוד שכתב או ביטל: קודם עדיין נרשם הטקסט המקורי באירוע user_prompt, ב-interaction span ובבקשות לכותרת סשן. נוספו גם מדדי כתיבת cache בנפרד ל-5 דקות ולשעה. אלה שיפורי תצפית; הם אינם מדיניות שמירה או הרשאת שיתוף.

המשכיות ועצירה

תוקנו חידושי headless/Agent SDK שאיבדו הודעות אחרונות או summary של compaction, או החזירו היסטוריה מלפניו. אחד התיקונים חל על compactions מהגרסה הזו ואילך, לא הבטחת תיקון של סשנים היסטוריים. תוקנו גם סשן ענן שעונה שוב אחרי restart ופקודות רקע שלא נעצרו: ביציאה הן נהרגות אם עדיין פועלות 1.5 שניות אחרי בקשת העצירה.

הגרסה גם מתקנת Write/Edit בענן שדיווחו הצלחה לנתיב במחשב המקומי בלי שהקובץ הגיע. הלקח הוא לא לסמוך על הודעת success כתחליף לקריאת היעד. תיקון MCP נוסף מונע כשל400 חוזר כש-API דוחה schema: הכלי נשלח ללא פרמטרים לשאר השיחה. זו התאוששות משגיאה, לא הוכחה שהכלי שימושי כרגיל.

חיבור אפשרי לפיתוח מענה, Podcasto ו-dorgames: אם משתפים תמליל debug, לבדוק את הקובץ המלא ולא רק צילום הצ'אט. בתהליכי פיתוח ארוכים כדאי לבדוק לאחר resume גם מה נשמר וגם מה השתנה בפועל. לא נבדקה הגרסה אצלך ולא בוצע שדרוג.

02Mastra 1.77: לריצה הישנה אין זכות להמשיך לכתוב+

החדש הוא החבילה, לא יום גילוי הבאג

@mastra/core@1.77.0 פורסמה ב-14.10 ב-11:29:32 בישראל, עם חבילות storage תואמות. ה-release כולל run fencing ותיקוני Observational Memory. חלק מ-PRי המימוש מוזגו קודם, ב-10 וב-11 באוקטובר; האות הוא הגעתם לחבילה החדשה ול-adapters.

למה lease לבדו לא מספיק

ריצה נתפסת כמתה, עותק חדש ממשיך אותה, והעותק הישן חוזר. אם שניהם כותבים לאותו thread, הישן יכול לדרוס את הודעות החדש. Mastra נותנת לריצה בעלות עם generation; storage תומך בודק את ה-fence בזמן הכתיבה ודוחה בעלות ישנה. claim נרכש ומתחדש בזמן הריצה. זו בדיקת בעלות במקום שבו הנתון משתנה, לא רק הבטחה של worker שהוא עצר.

התמיכה תלויה ב-adapter ובטופולוגיה. MongoDB replica set או sharded cluster משתמשים בטרנזקציה; standalone חוזר ל-PubSub lease ללא fencing. Cloudflare KV לא תומך. ב-Durable Objects וב-D1 הבדיקה אטומית לכל משפט SQL, אבל takeover באמצע כתיבה מכמה משפטים יכול להשאיר חלק שכבר בוצע. לא נכון לסכם זאת כטרנזקציה אטומית לכל פעולה בכל backend.

זיכרון שאפשר לאבד בלי למחוק הודעה

ב-Observational Memory, reflection מעבירה את הסיכום לדור חדש, buffering מוסיף observations ו-activation מוציאה הודעות מהקשר המודל. כשהצעדים חפפו, היה אפשר להוציא הודעות לפני שהתצפיות שלהן נשמרו בדור הפעיל. המודל נשאר בלי ההודעות ובלי התמצית.

התיקון מוסיף supersededBy ומחזיר תוצאת כתיבה מפורשת, למשל commitActiveObservations עם applied/reason. ההקשר מתקדם רק אחרי commit מתאים. מחברי PR25906 דיווחו על 415 מתוך 500 fuzz seeds שנכשלו בבסיס מול אפס בגרסת התיקון, ועל 2,173 קטעים שאבדו, נתקעו או הוכפלו במרוצי תהליכים מול אפס בתיקון. אלו בדיקות שלהם עם מודלים מדומים, לא הבטחת איכות זיכרון עם מודל אמיתי.

הגבולות שצריך לקחת לשדרוג

הגנת הדורות מלאה רק כשכל התהליכים שמשתפים DB מעודכנים. בניהול schema ידני יש להוסיף שדות וטבלאות נדרשים לפני שדרוג; Convex דורש redeploy. PR הזיכרון מציין בדיקות שלא הוכחו, ובהן Convex מקצה לקצה ו-mixed versions, וחפיפה חלקית שעדיין יכולה להכפיל observations. fencing של storage גם אינו exactly-once למייל, תשלום או API חיצוני שכבר הופעל: אלה זקוקים ל-idempotency משלהם.

חיבור אפשרי למענה ול-Podcasto: אם שני workers יכולים להתאושש מאותה עבודה, מספר ריצה ייחודי לבדו אינו דוחה את הכותב הישן. כדאי לבדוק generation בזמן שמירת תוצאה ולשמור מפתח idempotency גם ל-side effect חיצוני. זה רעיון לבדיקת תכנון, לא טענה שהפרויקטים משתמשים ב-Mastra או צריכים לעבור אליו.

03Agent-Native beta: אותה פעולה ב-UI ובסוכן, לא אותו סוג אישור+

מה הושק

Builder הכריזה ב-14.10 על beta של Agent-Native, framework TypeScript פתוח לבניית אפליקציות עם סוכן ו-UI. metadata הפרסום מציינת 18:00 בישראל; הריפו קיים ממרץ, ולכן זו הכרזת beta ולא המצאת פרויקט אתמול.

הארכיטקטורה שכדאי להבין

מגדירים פעולה אחת עם schema ומימוש. ה-UI קורא לה מקוד, הסוכן מקבל אותה ככלי, ואפשר להגיע אליה גם דרך HTTP, CLI, MCP ו-A2A. נתונים ו-application state משותפים נותנים לסוכן הקשר כמו המסך הפעיל והפריט שנבחר. הוא לא צריך ללחוץ על המסך כדי להגיע לפעולה. היתרון הנטען בזמן ובטוקנים אינו מגובה ב-benchmark בפרסום.

שלוש שאלות שונות על אותה פעולה

authorize שואל מי רשאי לבצע את הפעולה, ו-access או בדיקת row-level מגבילים אילו נתונים הוא רשאי לשנות. לפי התיעוד וקוד main שנקראו, ההרשאות נבדקות לפני המימוש בכל ששת מסלולי dispatch. התיעוד החי מציג authorize ובדיקת שורה; קוד main מוסיף גם access הצהרתי. זו הבחנת גרסה, לא הנחה שכל API קיים בכל התקנה. לעומתם needsApproval עוצר את לולאת הסוכן לאישור קריאה מסוימת; אינו תחליף לבדיקת הרשאה בשרת עבור HTTP או CLI.

ברירת המחדל של needsApproval היא false. כשהוא מופעל, UI האישור מחזיר מפתח המבוסס על שם הכלי והקלט; שינוי פרמטרים דורש אישור שונה. זה מנגנון מתועד, לא בדיקה עצמאית שהכול נאכף בכל host. תיעוד main מתאר גם MCP/A2A העוברים בלולאה, ולכן צריך לבדוק את מסלול האינטגרציה בפועל, ולא להניח שדגל אחד מכסה כל קריאה חיצונית.

חשיפה אינה הרשאה

אפשר להסתיר פעולות מהסוכן או מסוכנים חיצוניים. פרוטוקולים ציבוריים דורשים opt-in מפורש; אין להסיק שיצירת action הופכת אותה לאנונימית ברשת. קטלוג MCP מצומצם כברירת מחדל עם tool-search לטעינה לפי צורך, בדומה לשאלת הקטלוג במהדורת אתמול. קטלוג קטן אינו גבול אבטחה.

זה beta עם תשתיות auth, storage ו-collaboration, לא רכיב קטן שמוסיפים בלי שינוי תכנון. אפשר לפתח מקומית ולארח עצמאית, אך עדיין צריך לבחור בסיס נתונים, מודל, הרשאות ומדיניות שמירה. לא נבדקו כאן latency, עברית או בידוד multi-tenant מקצה לקצה.

חיבור אפשרי ל-Podcasto, מענה ו-dorgames: פעולה משותפת כמו שמירת טיוטה יכולה לשמור UI וסוכן באותה לוגיקה. פרסום תוכן או שינוי חיצוני צריכים גבול נפרד מטיוטה, וכל נתיב כניסה צריך אותה בדיקת בעלות. החלק השימושי הוא עקרון שכבת הפעולות המשותפת; אין המלצה להעביר את הפרויקטים ל-framework.
