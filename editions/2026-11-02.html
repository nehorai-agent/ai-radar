021.11: OmniDiff v0.3.0 - diff מודע-תוכן ב-Rust: קוד בתוך מחרוזות מקבל diff כקוד, וקבצים בינאריים מפסיקים להיות קופסה שחורה+

מה זה ולמה כאן

v0.3.0 שוחררה ב-1.11, ובמקביל Show HN שזכה ל-192 נקודות. OmniDiff הוא כלי diff ב-Rust שמבין את סוג התוכן: קוד לפי tree-sitter, תמונות, פונטים, PDF, ארכיונים וקטלוגי תרגום - כולל כ-git external diff, TUI אינטראקטיבי, תוספי VS Code ו-Neovim, ו-showcase בדפדפן עם 20 שינויי-קוד אמיתיים מול GNU diff.

מה חדש ב-v0.3.0

קוד של שפה אחרת שיושב בתוך מחרוזת מקבל diff כקובץ בפני עצמו: TSX בתוך שדה JSON של "content", shell בתוך בלוק run של YAML, CSS/HTML בתוך template literals, YAML בתוך DOCUMENTATION של Ansible. ההערכות (escapes, הזחות, אינטרפולציות) מטופלות לפי חוקי השפה המארחת, וכל עריכה מודגשת במקומה במקום span אחד מהשינוי הראשון לאחרון. רשימות class (JSX className, cn/clsx/twMerge וכו') מקבלות diff פר-מחלקה. ו-diff-ים גדולים מהירים ב-20-40%.

איך לקרוא את המספרים

הטבלה שמפרסם היוצר (מדידה עצמית על מחשב T14s): 98% משינויי קוד תחת 100ms, 70% "מושלם" ו-92% "כמעט מושלם" מול ground truth ידני; PDF - 57% מהירים אבל 100% מדויקים (עם הערה: פחות מעשרה מקרי מבחן). אלו מדידות self-reported עם מתודולוגיה גלויה ב-repo - יותר שקוף מהמקובל, אבל עדיין של היוצר. שים לב לרישיון: AGPL-3.0-only - מעולה לשימוש אישי ופנימי, דורש מחשבה לפני שילוב במוצר מסחרי סגור.

חיבור אפשרי לפרויקטים שלך: ל-dorgames זו כמעט מתנה: נכסים בינאריים (פונטים, PDF-ים של עיצוב, תמונות) ש-git תמיד הציג כ"Binary files differ" מקבלים diff מפורט - איזה glyph השתנה, איזה עמוד. למענה ול-Podcasto: diff מדויק יותר של קוד פירושו review אנושי (וסוכני) זול יותר - במיוחד כשהקוד יושב בתוך YAML של CI או JSON, בדיוק המקומות שהרגלי ההעתקה שוברים diff רגיל.

031.11: "דליפת מודל Mythos של Anthropic" ב-Hugging Face - כל הסימנים אומרים מתיחה, וסימן אחד אומר סכנה אמיתית+

מה בודקים לפני שמאמינים

הרשימה שמפרקת את הטענה: החשבון ("burner22") נפתח ב-23.10 - שבוע וקצת לפני "הדליפה"; המטא-דאטה פיזית לא סבירה (~6.8 טריליון פרמטרים מסוג U8, קובץ בן 7.7TB - לא בקנה מידה עם שום מודל ידוע ועם המבנה המוצהר); התיוג "numbat" לא תואם שום שם פנימי שדלף אי פעם; וב-HN עצמו מצביעים שהדפוס חוזר - לפני ימים סוכרך checkpoint של "Fable 5" ש"נמכר בפורום אפל". לעומת זאת: שורות לוג אימון שנראות "משכנעות" הן בדיוק החלק שהכי זול לזייף.

הסיכון האמיתי: custom_code

ה-repo מתוייג custom_code - טעינת המודל מריצה קוד Python שרירותי מהמוכר על המכונה שלך. זה וקטור תקיפה קלאסי: כותרת סנסציונית, חשבון חד-פעמי, וקובץ שדורש הרצה. הכלל הפשוט: checkpoint ממקור לא מאומת לא טוענים - ובטח לא על מכונה עם credentials. אם סקרן: לבדוק את הקוד עצמו לפני כל הרצה, בסביבה מבודדת בלי גישה לרשת ולמפתחות.

חיבור אפשרי לפרויקטים שלך: אותו כלל מהקלפים הקודמים, מופעל שוב: מקורות חדשים (תוסף, מודל, סקריפט) נכנסים לסביבת העבודה רק דרך ערוץ רשמי ומאומת - בין אם זה שוק תוספים של IDE או מאגר מודלים. ואם מישהו שולח לך "מודל שדלף" - הזכר איך בודקים לפני שלוחצים.
